# Current Canonical Spine

## Role in the live wiki cluster
- Strongest use: second-layer controller/repo-doctrine router after the small `current/` front door has already been read.
- Weak use: global first-stop note for every session, or substitute for project-specific/current notes.
- Authority boundary: concept-level harness spine for repo-current and controller-facing doctrine; it does not outrank `current/read-first.md`, the other `current/` spine notes, or project `read-first.md` notes for entry behavior.

## Recommended reading order
1. `current/read-first.md`
2. the rest of the `current/` spine (`about-me-and-how-to-work-with-me`, `active-intentions`, `environment-and-rules`, `current-vs-legacy`, `skills-and-agent-rules`, plus `active-plans` when handoff/next-step context matters)
3. relevant project front door such as `projects/codex-ratchet/read-first.md`
4. this page when the task needs second-layer controller doctrine, repo-current authority routing, or deeper harness loading order
5. the specific pages in the spine list below that match the actual task
