## 2. Seam 1 — hostile-corpus expansion (~30 new classes)

### 2.1 Corpus meta-schema upgrade (adopt first — it changes how every class is built)

From the hostile-test matrix + red-team §19:

- **Nearby legitimate control** required per attack: the test passes only when the attack is blocked *for the declared reason* AND a neighboring legitimate input stays accepted. Our current corpus is attack-only — over-broad filtering is invisible to it.
- **Seven result states**: `ATTACK_BLOCKED / ATTACK_DEFEATED_CANDIDATE / ATTACK_NOT_DETECTED / CONTROL_FALSE_POSITIVE / INCONCLUSIVE / NOT_RUN / NOT_APPLICABLE`. A random crash is not a successful control; `INCONCLUSIVE`/`NOT_RUN` never satisfy a floor.
- **Reporting rule** (CDRT-042, meta-relevant to our own corpus): report `N/N versioned classes passed`, never "all attacks defeated." Add rotating/generated variants per class; scan detectors for fixture-ID recognition (CDRT-021 — code that branches on canary names/env/size).
- **Frozen before run**: attack payload, expected detection, and neighbor control are frozen before execution; producer cannot edit them after start.
- **Mutation families** (15): sign-flip in native kernel, reorder noncommuting stages, delete load-bearing stage, reset at outer/inner seam, remove one SMT constraint, change one factor edge / unit / metric direction, replace computation with constant, swap independent impl for shared wrapper, remove certificate, change quantifier, point-estimate for interval, protected-root byte (mirror). "A control is suspicious if all these changes leave the admitted result unchanged."
- **False-positive floor**: the suite must NOT ban legitimate time/probability/equality/continuous-math/NumPy-satellite/quoted-words usage — one legitimate-neighbor case per release.

## 3. Seam 2 — the two known-open witness harnesses, now fully specified

### 3.1 Independence harness (fills the shared-semantic-builder debt)

From CHEAT-001/CDRT-013/CDRT-014 + fleet §12:

- Each lane receives only a **frozen mathematical contract + raw fixture** — never executable decisive common code.
- **Asymmetric mutation**: mutate Julia only → Julia changes, JAX does not; mirror. **Dependency kill**: kill either lane → that lane fails hard, no fallback.
- **Decisive-overlap classifier**: compare process/module dependency graphs; overlap classified `schema-only | fixture-only | decisive`; any decisive overlap fails independence. "`reads_peer_result: false` is insufficient."
- **Common-mode control** (the part asymmetric mutation cannot catch): two lanes can independently implement the same wrong equation. Requires a hand-derived exact-small oracle independent of both lanes, seeded common errors (wrong sign / cut / order / normalization / handedness / loop-swap) that must lose to the oracle; agreement without an independent semantic control = `INCONCLUSIVE_COMMON_MODE`, not conformant.
- **Independence vector, never a Boolean** (CDRT §18.2): report separately — semantic derivation / algorithm / source implementation / runtime / native libraries / compiler / hardware / fixture / evaluator / checker / administrator. Never emit `independent: true`; never say "fully independent."
- **Negative fixture exists**: the actual `qit_bidirectional_science_type1_type2_v0_{common,jax,pytorch}.py` packet, whose legs import `build_core_measurement()` from one `_common` module.
- **Third-process comparator** (fleet §12.3): comparison runs in a third process that cannot import either result constructor, recomputes canonicalization/units/comparison, records disagreement without averaging, and carries an 8-way error decomposition (representation / rounding / solver / discretization / sampling / projection / serialization / model-form).

### 3.2 Causal mutation-witness (fills the mutation-witness debt)

From CHEAT-025: a mutation test passing on file-difference alone is rejected. Requirements: (i) semantically-equivalent textual mutations leave the observable UNCHANGED; (ii) a mechanistically-wrong mutation CHANGES it in a predeclared direction/locus; (iii) metadata/hash fields are excluded from the observable (else the receipt's embedded source hash "detects" every mutation); (iv) data-dependence traced from mutated operation to observable. Companion (CHEAT-002): dependency-kill deletes the claimed backend op — observable must break; a diagnostic-only mutation must NOT break it; a leg where deletion changes nothing is classified `decorative`, not `load_bearing`.

### 3.3 Supporting harnesses worth queueing behind those two

- **Four-cell engine×checker matrix** (CDRT-002): engine and checker never promote in one approval; a pass available only in `candidate×candidate` is a policy migration, not maintenance.
- **Environment-identity closure** (CDRT-016/046): maintenance receipts bind full env identity; a near-identical wrong environment's receipt must not qualify a run (`BLOCKED_STALE_ESTATE`).
- **Current-run dependency-kill** (CDRT-015): fleet health ≠ run causality — each load-bearing lane's deletion must break the *current run*, not just its fixture.
- **End-to-end deletion witness** (CDRT §18.8): one whole-transaction object contract→ticket→engines→comparison→settlement→decision; deleting any load-bearing edge blocks the final result. Anti-claim-splitting.

## 6. The three master residuals (keep as standing warnings, not tasks)

The red team's own summary of what no in-repo control fully solves:

1. **Same-author problem**: different programs are not independent if one authoring path chose all their semantics; the subtlest form is a shared omission — the same model forgets the same owner constraint in contract, engines, and checker. Partial defense: authorship graph + withheld fixtures + seeded shared-omission tests. Full defense is human/owner-side.
2. **Observation vs mediation**: a process trace shows what its observer saw, not everything; "captured process tree" is not proof of complete mediation. Defense: escape-fixture battery + honest E-level wording.
3. **Frozen wrongness**: a perfectly deterministic system can become a very reliable mechanism for enforcing an LLM's replacement theory. Defense: the owner-obligation registry (blocked on your ratification) + adversarial near-models (correct vocabulary, one wrong relation each).
