# Issue audit and corrections

## Executive correction

The previous campaign made “prove the deformation ladder first” a blocking dependency for engine construction. That was scientifically cautious but operationally wrong for the owner's present goal. It prevented the project from obtaining the running objects that a later MSS deletion lattice actually needs.

The new order is:

1. construct many finite, constraint-aligned engines;
2. require real state-bearing records, resource, load, and active basin degrees of freedom;
3. compare exact behavior across separate language runtimes;
4. retain several non-equivalent working systems;
5. then run the expensive joint MSS/substitution campaign.

This relaxes promotion gating, not honesty gating.

## A. Problems found in the supplied engine baselines

### A1. M★ v2 was a strong basin census but an incomplete engine

Fresh reproduction confirmed that M★ v2 exactly regenerates both 256-state maps and sixteen basins per hand. Its independent verifier and four-lane retained envelope pass.

However:

- the reported `64 -> 192 -> 512` support sequence does not enter the transition;
- “nested basins” are macro/phase/predictive analysis partitions, not successive deformations of the state geometry;
- the extension fibre is a set of `O/B` endpoints, not an inverse image of a restriction map;
- pair settlement and path interference are measured but do not enter `SurfaceModel.transition`;
- basin stabilizers and phase counts are reported after the map and do not control a later engine state;
- `load_connected` changes `load_delta` accounting only; it never changes the map;
- there is no fuel/resource state, backpressure, stall, overload, or autonomous Type-1/Type-2 phase.

Correction in this lab:

- a real finite restriction/gluing diagram is enumerated independently;
- operational future sets are separately typed and nested by actual inclusion;
- capacity counts select the next visible state;
- algebra/fibre, record, fuel, load, and phase are state coordinates;
- full load changes the visible transition;
- severance must change visible behavior.

### A2. The I/J/K prototype was not an attractor engine

The 24-cell I/J/K prototype freshly passed its tests and checks. Its “one left / two right basins” are nevertheless 36-tick dominant-cell signatures, not recurrent basins of an exhausted functional graph. It also has no resource or load coordinate.

Correction: retain I/J/K as a field vocabulary, but use exact functional-graph basins and state-bearing load for the engine gate.

### A3. The older engine-emergence lab had the missing load controls but no nested geometry

The older suite freshly passed 20/20 jobs and supplied productive-current, exact stall, and overload-reversal controls. Those controls were not joined to M★'s finite checkerboard basins.

Correction: port the load logic into the basin engine. V1 now has both a deterministic finite fuel-to-load episode with backpressure and a downstream exact-rational steady cycle wrapper.

### A4. Several handoffs were evidence packets rather than runnable products

- The Fable handoff contains receipts but omits its executable source.
- The CB stress packet is not self-contained: documented paths are invalid, paired-envelope sources and formal resources are missing, and one Python battery exits zero with only 1/30 checks passing.
- Current JAX, PyTorch, and Julia receipts are valid historical/source-addressed evidence but cannot be called fresh runs on this host.

Correction: the new deliverable is self-contained for its actual CPython and Node.js lanes, and it names absent runtimes as absent rather than laundering old receipts into a new run.

## B. Strong ConstraintBox defects

The full audit is preserved in `CONSTRAINTBOX_SIM_INTEGRATION_AUDIT.md`. Two findings are release-blocking.

### B1. The public simulation-facing gate is weaker than the fired hook

The public `gate.py -> claim_verify.py` route admitted a shipped duplicate-key hostile claim. The full hook rejected the same bytes at strict intake. `sim_admission.py` currently calls the weaker route.

Correction in the contained lab controller:

- raw JSON rejects duplicate keys and nonfinite values before use;
- producer claims never authorize the result;
- every state except the one bounded eligible-execution state is non-admitting;
- the receipt remains non-promoting and external to the CB kernel.

This is a contained fixed-source repair pattern. It has not silently patched or released the upstream CB checkout.

### B2. A receipt can select Python code that the verifier imports

The archived attractor verifier reads a controller path from an envelope and executes it after checking only the envelope's self-declared hash. An isolated proof printed from the untrusted module before the invalid envelope was rejected.

Correction in this lab:

- the protected controller, compiler, two lanes, independent verifier, and campaign are resolved relative to the fixed package;
- all protected sources are hashed before execution and again afterward; any change blocks eligibility;
- an added `verifier_path` field is rejected by exact-schema intake;
- no code, command, runtime, verifier, tolerance, or verdict is loaded from a lane receipt.

### B3. Other controls added

The controller now proves:

- full-map mutation is rejected even when the producer still says `CLAIMED_PASS`;
- compiled-fixture severance is rejected;
- two separate language runtimes agree over all maps, extension sets, and traces;
- each runtime replays byte-canonically;
- a fixed spatial relabelling conjugacy preserves base-graph invariants;
- reversing arbitrary basin enumeration leaves every engine trace unchanged;
- fuel plus load is exactly conserved;
- full-load stall is exact;
- basin-only feedback severance is inactive in the null control and active in retained systems;
- same-initial-state backpressure disablement and phase-only shifts provide isolated visible witnesses.

## C. Mathematical corrections locked against narrative drift

The following Gemini claims are not carried forward:

- Groups, groupoids where composition is defined, semirings, and matrix multiplication are associative.
- Partial composition in a groupoid does not make it nonassociative.
- An irreversible transition system is ordinarily a transformation semigroup or path category, not a groupoid of invertible arrows.
- \(Q_8\) is noncommutative but associative.
- Bare Fano-coordinate XOR is the associative group \(C_2^3\), not octonionic multiplication.
- A repeated `O-B-O` word cannot expose intrinsic nonassociativity in flexible Moufang, octonion, or Jordan candidates; use independently instantiated operands.
- No executed test showed that a Fano rule preserves M★'s sixteen basins.
- Discrete Morse terminology does not prove automaton basin membership without a dynamics-linked gradient construction.
- A deterministic finite map has zero asymptotic topological entropy under the proposed signature-growth limit.
- Boolean/max-plus eigenvalues are not simply cycle lengths.
- M★'s oriented current is not Chern–Simons.
- A signed-seam/Q8 presentation witness is not a proof that the carrier is a Klein bottle.
- A cyclic fibre is not automatically Hopf structure.

## D. Remaining issues

### D1. The full engine graph is sampled, not exhausted

The visible 256-state maps are exhaustive. The full state

```text
(visible, algebra/fibre, record, fuel, load, phase)
```

can contain millions of states—about 23.9 million for the Jordan branch. V1 uses ten fixed seeds and 192 updates per hand. It finds many recurrent engine cycles, but it does not claim the complete full-state basin partition.

### D2. Two fresh runtimes are not the final estate

CPython and Node.js run and agree here. JAX, PyTorch, and Julia are absent. The next adapter campaign should implement the exact same compiled fixture in those three runtimes and let the same fixed controller compare raw observables. Until then, “new five-runtime engine parity” is false.

### D3. The schedule is an authored rival

The archive contains conflicting sixteen-count conventions. V1 pins an eight-stage schedule per engine, sixteen placements across the pair. It does not claim canonical recovery of every earlier schedule.

### D4. MSS is still pending

Capacity deletion is already measured, but the complete joint lattice over nesting, seam, algebra/fibre, record, bracket, feedback, controller, fuel, load, and backpressure has not been run. That is now a useful next step because multiple engines actually exist to prune.
