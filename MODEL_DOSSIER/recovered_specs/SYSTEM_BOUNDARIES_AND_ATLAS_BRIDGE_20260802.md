# System boundaries and Atlas bridge

The intake contains several systems that share language but answer different
questions. Keeping their authority separate is a core safety condition.

## 1. Four research/runtime surfaces

| surface | owns | does not own |
|---|---|---|
| Entropic Geometry | owner thesis, finite-first mathematics, physical and cross-domain hypotheses | runtime admission, proof of its own physics |
| Codex Ratchet | rival deformations, demand packets, settlement, plural frontier, Purgatory, next demands | full scientific simulation, product truth, LLM authority |
| Sim Engine | isolated scientific profiles, finite execution, measurements, controls, uncertainty, environment receipts | canon promotion, claim ceiling, Ratchet frontier |
| ConstraintBox | bounded request typing, capability health, evidence admission, ClaimGate, claim ceilings, public packets | manifold construction, engine dynamics, scientific conclusions |

An optional stack runner may move versioned packets between them. It owns no
scientific or evidential judgment.

## 2. Public packet loop

~~~
Codex Ratchet proposes a candidate packet
  → ConstraintBox validates type, permission, source, and claim ceiling
  → Sim Engine executes one bounded job in an isolated profile
  → Sim Engine returns measurements, controls, and provenance
  → ConstraintBox validates the receipt and admission boundary
  → Codex Ratchet updates the plural frontier or Purgatory
~~~

No core product may import a sibling's private modules, search for sibling
checkouts, infer schemas by similar field names, adopt a sibling's verdict, or
silently upgrade an environment.

## 3. ConstraintBox boundary

The source design keeps ConstraintBox lean and Python-aligned:

- standard-library ledger, hashing, paths, subprocess control, and CLI;
- JSON Schema validation;
- bounded SMT profiles such as Z3/CVC5;
- optional small symbolic/graph/numeric adapters.

JAX, PyTorch, Julia, QuTiP, Quimb, Cotengra, PySINDy, CUDA, and cloud GPU
dependencies belong to Sim Engine profiles, not the controller core. A
ConstraintBox adapter may call a public Sim Engine capability, but it must know
only the capability ID, health, environment digest, contract, and claim
ceiling.

ConstraintBox evidence admission is not scientific admission. A receipt can
be validly formed and still report a bounded negative or an unearned model.

## 4. Sim Engine profile estate

The source material proposes isolated profiles:

| profile | role | candidate tools |
|---|---|---|
| finite reference | exact enumeration, controls, portable fixtures | Python, NumPy, SciPy, SymPy, NetworkX/Rustworkx |
| topology/dynamics | complexes, homology, basins, identification | GUDHI, TopoNetX, PySINDy |
| quantum information | states, channels, trajectories, tensors | QuTiP, Quimb, Cotengra |
| JAX | vectorized/differentiable execution | JAX, Diffrax, Lineax, JAXopt |
| PyTorch | graph/autodiff independent lane | PyTorch and selected geometry tools |
| Julia | independent semantic/referee lane | pinned Julia project and selected QIT/tensor packages |
| GPU/cloud | large sweeps and high memory | capability-specific images |

Each profile owns a lock/manifest, source or image digest, hardware/precision
policy, import and API tests, positive and negative fixtures, packet versions,
and its own claim ceiling. A profile failure parks that capability; it does
not make unrelated profiles unavailable.

## 5. Leviathan Atlas overlay

Leviathan Atlas is a local-first product and interpretation surface:

~~~
Mirror = the node seeing its own language, sentiments, and projects
Atlas  = a local map of objects, constraints, basins, and futures
Lens   = a bounded projection composed for a purpose
Mesh   = relations among sovereign nodes through Lenses, work, teaching, and results
Build  = selected path becoming procedures, gates, and action
Observe = results revising the model
~~~

The product should render a plural map before forcing clarification, preserve
candidate meanings, bind abstract language to particulars and procedures, and
make source traces and unresolved items visible. It must not give an LLM fluent
language execution authority or treat IGT/personality labels as settled
identities.

Atlas may consume:

- a Ratchet candidate packet;
- a ConstraintBox capability/evidence receipt;
- a Sim Engine result packet;
- owner correction and source traces.

Atlas does not replace the Ratchet, ClaimGate, or scientific profiles.

## 6. Source authority ladder

When documents conflict:

1. direct current owner prompt/correction;
2. direct runtime contract or source-native executable artifact;
3. exact owner/source conversation and authored file;
4. validated receipt and current evidence audit;
5. integrated synthesis;
6. legacy/generated narrative;
7. MMM and snippet dictionaries for salience only.

The ladder is for routing and claim ceilings. It does not allow a synthesis to
rewrite the source that it summarizes.

## 7. External-result seam

The bridge is an artifact seam, not shared in-memory state:

~~~
request packet → public capability ID → isolated execution
             → result/provenance packet → ClaimGate/evidence receipt
             → Ratchet/Atlas update
~~~

The current source records a real bounded exchange pattern between local nodes,
but that is not proof that the full human social Atlas/Mesh or the full Lev
runtime is integrated.

## 8. What the bridge must never do

- turn a source receipt into a physical truth claim;
- call a topology loop an engine;
- let a simulator mutate the Ratchet frontier directly;
- let ConstraintBox become the manifold or Sim Engine;
- let an MMM seed outrank owner/source/evidence authority;
- publish a private Mirror as a public social object without permission;
- embed a particular LLM, provider, or personal budget as a model axiom.

The bridge exists to preserve separation while making valid work composable.
