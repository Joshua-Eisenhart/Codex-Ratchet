# Red-team gate audit — 2026-07-24

Targets: `claimgate_plugin/intake_supervisor.py` and `system_v8/harness_patch/harness_gate.py`.
All probes were executed locally with Python 3.13. No source fixes were made. Fixture directory for the run was `/private/tmp/redteam-luna-wcf_1_lm`; the floor store was `/private/tmp/redteam-luna-wcf_1_lm/store.json` containing `{"floors":{"locked_metric":0.9}}`.

## Executive result

Two high-severity harness bypasses are confirmed. `harness_gate.py post` returns exit **0 / ADMITTED_WITHIN_CEILING** for an overflowing numeric literal, nested non-finite poison, and a locked metric identifier appearing only as a value. The harness never invokes the intake supervisor or performs locked-floor/numeric-array validation.

The path pre-check also returns exit **0 / ROUTE_SEALED** for all tested path forms. This is expected to be a route eligibility result, not proof of a write; however, the check is TOCTOU-unsafe because no sealed handle or post-write revalidation exists.

Severity ranking:

1. **Critical — post-gate validation bypass.** `1e400`, nested `"NaN"`, and locked-id-as-value are admitted by `post`.
2. **High — TOCTOU path authorization.** A checked symlink can be swapped before the worker writes; `pre` returns 0 and there is no enforcement in this file after that point.
3. **Medium — intake numeric blind spots.** `intake_supervisor` accepts `1e400`, `-0.0`, and a non-finite string in a dict value when no floor store causes PARK.
4. **Low / no bypass observed — duplicate-key, BOM, UTF-16, confusable, and floor case/value attempts.** These were rejected or parked by intake.

## Path checks

The harness ticket was minted with `--tools Write --roots /private/tmp/redteam-luna-wcf_1_lm` (mint exit 0). Each command had exit **0** and emitted `ROUTE_SEALED` / `within ticket scope`:

```sh
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/real/x
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/real/
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/real/./x
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/link/x
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/hard2
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/café
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/café
python3 system_v8/harness_patch/harness_gate.py pre --tool Write --path /private/tmp/redteam-luna-wcf_1_lm/REAL/x
```

The `link` path resolved correctly before the check. A TOCTOU probe then ran `pre` on `/private/tmp/redteam-luna-wcf_1_lm/race/new.txt` (exit 0), swapped `race` from `safe` to `unsafe`, and observed no subsequent enforcement because this module performs no write and returns no capability/handle. This is a confirmed authorization-window design flaw, not proof that this file itself performed an unauthorized write.

Hardlinks are not meaningfully constrained by lexical path resolution: the `hard2` path was also sealed (exit 0). On this host, the case-variant path was nonexistent and was still sealed under the allowed lexical root; that is weaker than an APFS-specific proof but exposes the same missing existence/inode identity check. NFC and NFD paths were both sealed (exit 0); no normalization-equivalence policy exists.

## Root cause

`harness_gate.py post()` calls `_strict_load`, checks only top-level self-verdict field presence/truth, and requires `classification`. It does not call `poisoned_numeric_arrays`, `locked_floor_check`, or any finite-number walk. `pre()` canonicalizes only at check time and returns an advisory route seal; it does not bind the eventual write to an opened inode or revalidate after the operation.

No fixes were applied.
