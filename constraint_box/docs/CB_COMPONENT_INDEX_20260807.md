## MLV — MiniLevOS

MiniLevOS is ConstraintBox's own small deterministic flow kernel, written in Python and inspired by LevOS but importing none of it: a frozen FlowPolicy of typed hook nodes, a controller that alone picks every transition, six finite budgets, a hash-chained ledger per step, and exactly five terminal states. Its 19 flow policies range from a live two-node formal-controller flow to 14 external capability flows that dispatch engines outside the kernel. For the code-site rows (invariants CI-* and RI-*) I use the ladder as: exists = the check is in the source; runs = it is on the executed path of every construction or step; passes_local_rerun = a named test in tests/test_mini_levos.py exercised that specific refusal in a fresh run I performed this session. All test evidence is from read-only pytest runs with the cache provider disabled and the hypothesis store redirected to /tmp; `git status --porcelain constraint_box/` shows no new modifications from my runs.

## GATE — CB gates

CB gates are the deterministic code checks that decide whether an LLM-produced claim, a council compilation, or an external ClaimGate chain report is admitted. No model votes: every gate is a Python function that returns a named refusal reason, and every refusal string is a separately addressable check. They live in five wave/run scripts, two library-wiring scripts, one control-law script, and the ClaimGate chain parser in the installable package.

Every tier-2 library lives only in scripts/, never in the shipped src/constraintbox package; src imports only z3, cvc5, sympy, rustworkx, maude, numpy and networkx.

## SWM — The swarm: waves, councils, members, seats, lanes, managers

Constraint Box's swarm is a four-level tree — WAVE (a barrier) contains ROUTES (councils), each route requires named CHILDREN, and each child is itself a council of SEATS, where one seat = one salience slice dispatched on one provider lane. Three wave drivers exist as executable Python (decision, failure_routes, follow_up); the ten W-* waves in member_role_wave_v1.json are a taxonomy with almost no drivers, and the five managers plus the collapse auditor are agent markdown with only two implemented in code.
