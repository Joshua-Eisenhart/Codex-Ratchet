# ConstraintBox product contract

This is the current bounded owner-object projection. It is a navigation and
acceptance document, not permission to promote a result.

## Product

One restartable ConstraintBox package with one public `cb` command and four
explicit parts:

1. **CB Light** — deterministic Python, schemas, probes, SMT, gates, state,
   receipts, and verification. Models never set a disposition.
2. **ZIP Agent** — the stateless communication protocol. CB opens a validated
   packet, gives declared files to short-lived workers, validates returned
   files, performs bounded retry or rejection, and emits a digest-bound return
   ZIP. A chat answer is not a ZIP result.
3. **JAX/QIT profile** — a separate project-neutral interpreter installed from
   the shipped lock. It produces numerical observations; it cannot enter Light
   or promote itself.
4. **Waves** — contained, callable procedures composed from skills, tools, MMM
   salience, bounded loops, and receipts. A Markdown file or `wave.json` alone
   is not a runnable wave.

Host hooks are plural, thin adapters around this product. They remove an
unmanaged model's execution authority and relay a request into CB. A hook is
not CB, does not choose models, and does not make semantic decisions.

## Required behavior

- Models, providers, budgets, council widths, and MMM selections are run data;
  no model roster is kernel law.
- Light and the JAX/QIT profile remain separate interpreters. Light importing
  JAX is a failure.
- Prompts, skills, MMM bytes, task identities, ancestry, retries, declared
  outputs, and return bytes are hash-bound in ZIP work.
- Cancellation, timeout, bypass, missing evidence, and nonzero children are
  visible terminal outcomes; none is rewritten as success.
- Probes, maps, basins, and gates remain different objects. A graph component
  is not an attractor without a declared update rule. A wave is not a gate.
- Probes are operation-specific and include negative, boundary, replay,
  mutation, ablation, and order controls. Import success alone does not make a
  Python library useful.
- Project state survives a crash without relying on an LLM's chat context.
  Owner prompts and plan/progress events remain in the append-derived corpus.
- Human output is compiled from receipts into a stable, compact form showing
  what ran, what failed, model/agent depth, tool counts, holds, unknowns, and
  proposed next prompts.

## Mathematical boundary

The current finite research object is probe-relative. It investigates one
entropy/time gradient with two ordered readings. `open` is declared support
extension; `bind` is restriction induced by named probe/constraint rows.
Generic noncommutation is not chirality, ratcheting, or a manifold.

Hartley support capacity, fibre capacity, record capacity, Hopfield energy,
and memory count remain distinct quantities. Entropy/topology coupling and
spinor/Hopfield memory are hypotheses to probe, not package authority.

## Explicit exclusions

- No Archive or versioned historical project is a live dependency.
- No global `~/.codex/skills` or provider session is product authority.
- No copied virtual environment, provider credential, model session, or raw
  campaign row dump is shipped in the release ZIP.
- No model-backed failure/repair/strategy wave is called runnable until its
  complete contained child graph and receipts execute.
- No physical time, physical manifold, quantum advantage, attractor basin,
  scientific engine, CB Heavy readiness, portability, or promotion claim.

## Release acceptance

The release is accepted only when a fresh extraction can:

1. verify the archive manifest and every file digest;
2. bootstrap Light from its included lock;
3. plan/install or safely adopt and probe the separate JAX/QIT profile;
4. show Light cannot import JAX and the attested JAX profile can;
5. build, execute, replay, and verify a model-free ZIP job;
6. list waves truthfully and run the admitted maintenance, context-strategy,
   and exploration cohort;
7. run the structured operation and the bounded Mini-Lev path-mass operation,
   including their negative controls;
8. verify prompt-corpus custody and current compact projections;
9. find no active absolute home, old project, Archive, or global-skill binding;
10. write all new receipts outside the immutable ZIP payload.

Promotion remains false after these checks. They establish a runnable local
product, not every deferred claim.
