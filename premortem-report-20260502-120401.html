Premortem Report: Three-Wave Wizard

Premise: six months from now, the three-council Wizard redesign failed. This report works backward to harden the design before adoption.

Most likely failure

Council wrapper sprawl

The new councils become prettier labels around old voice/lane complexity unless role contracts and receipt boundaries are enforceable.

Most dangerous failure

Failure Council softens

Unsupported decisions survive as caveated follow-ups, weakening the very gate meant to protect Wizard from overclaiming.

Hidden assumption

Cleaner structure creates cleaner behavior

It will not. Behavior changes only if verdicts, canonical receipts, liveness state, and actionability are hard gates.

Revised Three-Wave Design

Wave 1: Decision Council

Choose one bounded move now, preserve one or two live alternatives, and freeze raw receipts before failure pressure begins.

Wave 2: Failure Council

Read Decision raw receipts, not polished synthesis. Return kill, quarantine, harden, or pass.

Wave 3: Follow-up Council

Generate divergent next lanes after Failure status, then audit to executable next moves with target, check, and done condition.

Soft Failure Gate

Receipt Inflation

Assumption: More parallelism would beat coordination debt.

Warning: Spawned counts outrank accepted canonical receipts.

Prompt Theater

Story: Follow-ups sounded sharp but did not name file, command, check, owner, or done condition.

Assumption: Better prompts naturally become executable actions.

Warning: Many repeated labels, few changed files or verified results.
