# V5 Rebuild Goal Prompt

Use this as the current compact `/goal` prompt for the v5 clean rebuild work.

```text
/goal Rebuild SIM/QIT work cleanly in v5 while using v4 only as reference.

Read:
- system_v5/docs/V5_CLEAN_REBUILD_CHARTER.md
- system_v5/docs/V5_REBUILD_ROADMAP.md
- system_v5/docs/GEOMETRIC_CONSTRAINT_MANIFOLD_FORMAL_SCOUT_CONTRACT.md
- system_v5/docs/MULTIMODEL_PROPOSAL_SPLIT.md
- system_v5/ops/queue_cleanup/probe_folder_rebuild_inventory_20260514.md
- system_v5/ops/formal_scouts/README.md

Split:
- system_v4/probes = reference corpus/evidence mine only.
- system_v5 = clean rebuild surface.
- system_v5/grok_sim = informal proposal/failure lab only, never evidence.

Principle:
Bounded does not mean conservative. It means maximum exploration under maximum
constraints, like actual evolution: branch hard, prune hard, keep receipts,
preserve deaths, and never promote survivors beyond their evidence.

Do:
1. Cleanliness: record git status counts before/after each batch; separate
   pre-existing dirt from new changes; keep new files inside declared v5
   surfaces; remove runtime byproducts; no bulk staging.
2. Transfer: mine v4 for real callables, receipts, ceilings, and graveyards. Do
   not copy dirty files as authority. Wrap/re-express useful math in clean v5
   harnesses with literal math names.
3. Formal scouts: build under system_v5/ops/formal_scouts. Each receipt needs
   classification=formal_scout, promotion_allowed:false, claim ceiling,
   observable, predicate, boundary, graveyards, nearby-variant summary,
   blockers, why_not_v4_probes, exact callable paths.
4. Providers: use Grok/Gemini/Sonnet for divergent proposals, tower orders,
   couplings, attacks, and poor-gate findings. Codex verifies repo grounding,
   no-hardcoding, names, receipts, and ceilings before translation.
5. Probe cleanup: inventory system_v4/probes by tracked dirt, untracked
   generated waves, naming contamination, admitted/reference, source-only,
   result-only. Move/rename only by manifest. No broad delete.
6. Gate quality: identify gates that are too strict, too weak, stale,
   decorative, or blocking useful exploration. Propose better gates that reject
   bad evidence without stalling formal-scout work.

Soft blockers: final proof, unique layer order, full physical graveyards,
historical naming cleanup, canonical manifold/bridge/cycle/axis interpretation.

Hard blockers: no receipt, no claim ceiling, hardcoded callable substitute,
hidden density/dimension failure, no graveyards, scout promotion claim, new
exploratory output in v4/probes, provider output treated as evidence.

Naming: new executable names describe the math directly. Avoid axis, engine,
gstack, rosetta, type1/type2, personal labels, target-system labels. Reused old
files get clean v5 wrappers or manifest renames.

Git: stage only named paths after inspecting diff. Keep docs/source/results/
runtime cleanup in separate checkpoints. Re-check staged diff before commit. Do
not stage large generated inventories unless explicitly making an evidence
snapshot.

Done for a batch: updated support docs or roadmap, v5 formal-scout or
blocked-reason receipt, provider proposal record, probe inventory/manifest or
gate-quality finding, validation/preflight output, git status summary, and a
narrow commit/push if files changed.
```
