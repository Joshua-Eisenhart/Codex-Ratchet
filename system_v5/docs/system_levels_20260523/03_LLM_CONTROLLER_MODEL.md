# LLM Controller Model

Date: 2026-05-23

Status: LLM-facing guidance. Not canon by itself.

## 1. Main Job For LLMs

An LLM working on this repo should turn unclear ideas into bounded,
checkable work without flattening the owner's thesis into generic quantum or
FEP language.

The agent should preserve five distinctions:

```text
owner thesis != root constraint
root constraint != derived constraint
derived constraint != operational gate
formal scout != admission
failed sim != useless work
```

## 2. Required Translation Pattern

When a user gives a high-level idea, translate it as:

```text
1. human thesis
2. QIT/math form
3. CS/runtime form
4. finite carrier
5. finite operations
6. finite controls
7. expected readouts
8. claim ceiling
9. next smallest scout
```

Do not jump directly from idea to canon.

## 3. Words That Need Fencing

### Axiom

Ask which role is meant:

```text
owner_thesis
root_constraint
derived_constraint
process_law
sim_gate
receipt
```

### Entropy

Never assume entropy is a root.

Use:

```text
owner thesis: entropy is central
formal object: entropy readout over finite admitted carrier
```

### FEP

Never import classical FEP directly.

Use:

```text
finite QIT-FEP
relative entropy
finite instrument histories
process tensor or density state
no primitive probability
no primitive time
```

### Axis0

Never say Axis0 is solved because one scalar worked.

Use:

```text
Axis0 candidate family
cut-history polarity
separable readouts
controls
admission pending Xi bridge
```

### Flux

Never say flux is root.

Use:

```text
derived current family
manifold/engine binding candidate
steering current
needs multi-seed/topology/carrier testing
```

## 4. Overclaim Filters

Before writing a conclusion, apply these filters:

```text
Did a sim actually run?
Was the result freshly rerun?
Was a matched control used?
Was the claim already killed by a graveyard row?
Is this a single fixture or a family?
Is this a source translation or an admitted result?
Is this a QIT object or classical language renamed?
```

If any answer is unclear, lower the claim.

## 5. Correct LLM Output Shape

For explanations:

```text
plain language first
then operational translation
then what is tested
then what remains open
```

For repo work:

```text
files changed
commands run
results
blockers
next concrete step
```

For theory:

```text
thesis
candidate math
root pressure
controls
falsifier
smallest scout
```

## 6. What LLMs Must Not Do

Do not:

```text
rename classical probability as QIT probability
rename Markov chains as quantum because matrices are present
call an audit a proof
call a formal scout canon
collapse Holodeck, FEP, Axis0, and flux into one thing
declare old legacy docs correct without a fresh gate
use "physics model" to skip mathematical proof obligations
```

## 7. The Best Default Framing

Use this as the default frame:

```text
The geometric constraint manifold is the emergent ratchet and attractor-basin
surface generated by F01 and N01. The QIT engine runs lawful finite
transformations on that surface. The Holodeck is the practical FEP engineering
loop. Axis0 and flux are candidate readout/current families that must survive
controls.
```
