Status: working intake and translation guide. Not canon by itself.

This document processes three old high-entropy legacy sources named by the
owner:


The files are useful, but they are not safe as authority. They contain owner
ideas, generated elaboration, metaphor, premature physics claims, old naming,
and possible hallucinated certainty mixed together.

The correct use is:

```text
legacy source -> extract owner pressure -> translate to finite QIT/CS form
-> design controls -> run sims/proofs -> only then update status
```

## 1. What These Sources Are Good For

The legacy docs are valuable because they preserve conceptual pressure that
newer operational docs can flatten:

1. the "fuzz" or maximum-entropy starting intuition;
2. entropy/information as the bridge language;
3. identity as similarity or distinguishability, not primitive equality;
4. future/prediction/possibility pressure;
5. nested Hopf/spinor geometry as a natural carrier candidate;
6. polarity and feedback loops;
7. Holodeck as practical predictive world-model, not just metaphor;
8. Type 1/Type 2 engine language;
9. Szilard/information-to-work intuition;
10. operator families attached to real mathematical patterns.

They are also useful because they expose old errors.

Common errors:

1. treating infinite fuzz as primitive;
2. treating entropy monism as proven physics;
3. using "probability" before naming a probe;
4. treating time, causality, metric, and coordinates as if they were admitted;
5. treating psychological labels as physics;
6. claiming "derives GR" or "solves physics" from suggestive formulas;
7. using old Axis/flux language as if it were current receipt status.

The useful job is not to copy the old docs. The useful job is to distill them
into testable QIT/CS candidates.
