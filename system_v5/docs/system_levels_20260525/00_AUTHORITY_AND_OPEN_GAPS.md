### Spinor Enforcement

Spinor space is load-bearing. Density matrices are allowed as readouts or
working carriers after finite probe/effect admission, but they cannot replace
the spinor/Hopf/Weyl carrier in new nonclassical manifold work.

Unsafe:

```text

Pauli axis = root geometry
Cartesian xyz = shell geometry
scalar PEPS3D label = PEPS3D carrier
```

Safe only when explicitly fenced:

```text
Bloch/density/Pauli charts as adapters or controls
torch-native density from spinor psi psi^dagger
finite effect responses over named probes
finite PEPS3D tensor sites carrying spinor-derived data
```

### Axis0 Collapse

Axis0 is not a solved scalar, and Axis0 zero is not "the i scalar equals zero."
The `i`-scalar has a real genealogy in the owner/wiki Axis0 cluster, but it is
not the same object as the current executable Axis0 cut readout. The current
safe split is:

```text
i-scalar genealogy:
  shell/order/universal-clock candidate, open

quaternion carrier:
  S^3 = SU(2) = unit quaternions, carrier geometry

flux:
  candidate derived pure-quaternion current J = i J_i + j J_j + k J_k

Axis0:
  downstream signed/cut/history/feedback readout family, open_partial
```

Those four objects can interact later. They must not be collapsed now.

### PEPS3D From The Start

PEPS3D is not a late proof layer after stage labels. It is the finite
spinor-network carrier from the first admitted finite carrier/probe step in new
nonclassical manifold work. A 16-stage scaffold plus 64 operator rows is not a
64-cell PEPS3D manifold unless each cell has local state/action evidence or a
projection from a richer finite PEPS3D carrier.

### Quaternion Language

Quaternion language is admissible only when the map/invariant is explicit:

```text
q_v in H_1
q_v = z_1 + j z_2 for psi_v = (z_1, z_2)
I_quat(v,w) = q_v^{-1} q_w or an equivalent finite invariant
```

Naming `i`, `j`, and `k` is not enough. The sim or proof must say what the
quaternion map changes, preserves, blocks, or measures.

### Engine Fe Mismatch

Current source/runtime surfaces still contain a source-conformance issue:
`canonical_qit_engine_specs.py` and the explicit 64-substage scout do not fully
agree about the `Fe` operator realization. Until that is repaired, the engine
docs can preserve the four-operator grammar and row counts, but they cannot
claim final `Fe` dynamics.
