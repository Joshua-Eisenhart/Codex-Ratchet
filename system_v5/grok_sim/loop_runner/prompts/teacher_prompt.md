# Teacher prompt — sent to Grok between iterations

Generated by Opus from the Auditor's diagnosis. This is the ONLY feedback that
goes to Grok. Audit internals (regex patterns, threshold values, hidden tests)
are NEVER included.

## Output shape (what Opus produces for Grok)

```markdown
# Iteration N — patch request

Your candidate did not pass phase {phase_id}.

## What's working (preserve these)
- {list of passing checks, expressed in math terms}

## What needs fixing
For each failing check, in plain math:
- {check name}: {math diagnosis from Auditor, no regex citations}
  - Specific guidance: {minimal patch suggestion — what to change in the code}

## Smallest next move
The smallest change that would address all failures: {one paragraph}.

Do not rewrite the whole candidate. Edit only the functions that need to change.
Keep the API surface intact — the runner imports your functions by name.
```

## Teacher rules (Opus enforces internally)

1. **Smallest patch first.** Do not ask Grok to refactor more than necessary.
2. **Math, not regex.** Cite operator choices, initial states, numerical values.
   Never cite "the audit checks for `Ax\d distinguishable: True`" — that leaks
   the harness shape.
3. **Preserve working functions.** Name each function that's already passing
   and tell Grok not to touch it.
4. **One patch per iteration.** If multiple checks fail, fix the most upstream
   one first (e.g., if `run_engine()` returns wrong shape AND
   `compute_axis_metrics()` is also failing, fix `run_engine()` first).
5. **No new requirements.** The frozen phase contract is the contract.
   Do not add new acceptance criteria mid-iteration.
6. **Surface graveyard hints when relevant.** "Note: the audit also has a
   silent check that nearby-failure-cases die. Your candidate should fail in
   the obvious-wrong-direction too." But never name the specific graveyard
   regex.

## Example output (good)

> Your candidate did not pass phase 01_axioms.
>
> **Working:** `run_engine()` returns the right shape; M-equivalence demo
> correctly shows distinct matrices share probe class; finite_witness correctly
> varies with truncation parameter.
>
> **Failing:** the non-commutation pair test. `trace_distance` is reported as
> 0.000028. Likely cause: your A and B operators both act on qubit 0 with the
> SAME Pauli generator (σ_x rotated by different angles). σ_x rotations
> commute among themselves. Pick A on σ_x and B on σ_y (different generators
> on the same qubit), OR keep generators on different qubits and start from a
> state that's not in their joint eigenspace.
>
> **Smallest move:** in `noncomm_pair()`, change B's generator from σ_x to σ_y.
> Leave everything else alone.

## Example output (bad — don't do this)

> "Your trace_distance is 0.000028 but the audit threshold is 1e-3, so you need
> to get above that. Also the regex r'Non-?comm.*differ:?\s*True' is failing."
>
> Why bad: leaks the threshold AND the regex. Grok will satisfy both by
> hardcoding `print("Non-comm differ: True")` next iteration.
