**Created:** 2026-07-09
**Status:** proposed; ready for bounded implementation
**Classification:** implementation plan, not evidence
**Primary target:** one end-to-end SME object workflow with measured engine, learning, perception, and Lev receipt boundaries

## Viability Verdict

The bounded system is buildable from the current repo. The grand system is not yet established.

Already executable:

- cross-runtime 1q/3q engine calculations;
- a 300-tick dual-engine scratch loop;
- a 16-channel affine re-identification result over the proxy namespace
  `8 terrains x 2 selected/native operators`, not the 16 signed source slots;
- a source linter for 16 signed macro slots and their proposed 16 x 4 expansion;
- 64 independently probed terrain/sign/operator channels under one finite
  parameterization;
- a 64-slot ordered object-card scout;
- a five-view projection battery;
- bounded Type-1 and Type-2 science-method trials;
- a PyTorch trainable readout leg;
- evidence-only CR-to-Lev envelopes and a local verifier-quorum design.

Not yet earned:

- a dual-ratchet experiment that derives four sequential substage survivors
  from independent geometry and entropy ratchets;
- necessity of all 16 macro slots or all four substages;
- 64 independent intelligences or personalities;
- stable Type-2 equivalence across seeds;
- learning that changes engine dynamics rather than a bounded readout;
- perception over real noisy multimodal inputs;
- production object formation, MMM writing, or ontology authority;
- ProofBundle-bound, idempotent Lev consumption of the current evidence family;
- mesh projection or state mutation;
- Axis0, full manifold, FEP, physics, or nonassociative-DPI theorem closure.

The operational path must therefore build a useful object-evidence system without waiting for the deepest theoretical program. The math program remains a parallel falsification lane.

## Done Condition

The first operational rung is complete only when a frozen industrial-maintenance fixture passes this end-to-end path:

```text
heterogeneous views
  -> candidate root object
  -> Type-1 and Type-2 engine passes
  -> measurements and counter-projections
  -> action or discriminating-measurement request
  -> changed or newly selected world observation
  -> trainable PyTorch readout on train data only
  -> held-out falsifier
  -> signed object/evidence receipt
  -> Lev RunEvidence + ProofBundle validation
  -> idempotent k-of-n local quorum
  -> explicitly authorized mesh projection
```

All of these must be true:

1. The root object ID is never present in model features.
2. Held-out views bind to the right object above a preregistered threshold.
3. Ambiguous and contradictory views are refused or retained as unresolved claims.
4. Type-1 and Type-2 show reproducible, statistically distinct error profiles on the same objects.
5. PyTorch improves a held-out metric over frozen, shuffled-label, static-feature, and majority baselines.
6. Julia and JAX independently replay the frozen object and gate calculations within tolerance.
7. Lev consumes the receipt twice with one durable identity and no duplicate mutation.
8. A failed quorum cannot project to the mesh.
9. A passed quorum can project only through an explicit host-owned policy.
10. Every output keeps source evidence, anti-hashes, rejected alternatives, and claim ceiling.
11. One frozen authority manifest names the branch, source files, fixtures, commands, seeds, and hashes needed to reproduce the run.
12. The claimed 16 x 4 path consists of 16 parsed source slots whose
    substage classes are emitted by dual ratcheting, then execute sequentially
    under one inherited Axis-6 precedence sign; independent one-step channel
    probes and four narrative phases do not meet this condition.
13. Engine actions causally change or select subsequent observations; a fixture-driven belief-only loop does not satisfy the done condition.

## Fixed Pilot Object Family

Use one blue-collar maintenance domain before generalizing.

Candidate root object:

```text
maintenance incident on asset P-204 at job site J-17
```

Independent views:

- technician free-text note;
- work-order record;
- asset-registry row;
- parts invoice / catalog match;
- vibration or temperature sensor summary;
- later: one equipment image or inspection photo.

The fixture must contain multiple incidents on similar assets, reused part numbers, conflicting timestamps, aliases, missing fields, and at least one genuinely unresolved collision. A trivial one-object dataset is forbidden.

## Work Packages

### WP0 - Freeze Authority And The Existing Teeth

**Purpose:** establish a reproducible baseline before adding product behavior.

Build:

- one authority manifest that pins the repo branch, checkout, source files, fixtures, commands, runtime versions, seeds, and expected output paths;
- one source parser that yields exactly 16 macro-stages and a declared
  candidate pool of operator transitions from the atlas or source contract;
- three explicitly named namespaces: the 16 signed source slots, the proxy
  `8 terrains x 2 selected/native operators` fingerprint set, and the
  proposed 16 x 4 expansion;
- independent geometry and entropy survivor ledgers whose intersection emits
  the substage count; no four-count or operator list may be hard-coded into the
  admission gate;
- the already-passing `four_substages_dual_product_v0` prerequisite, which
  conditionally recovers the four source operator cells and one MSS square
  cycle but does not yet establish sequential stage dynamics;
- `engine_dual_ratchet_substage_emergence_v0`, which derives the minimal
  stage-bound survivor classes from a declared superset, then tests whether
  the product-square cells are independently recovered and runs the resulting
  sequential maps while holding each macro-stage's precedence sign fixed;
- an explicit distinction between operator transitions and the current `candidate -> measurement -> gate -> receipt` narrative wrapper;
- a preregistered 20-seed census for `stage_reid_16_v1`;
- a preregistered 20-seed census for `t2_order_carried_v1`;
- source/result hashes and seed plan written before expected outcomes are opened;
- a result that distinguishes stage identity, order sensitivity, and content-equivalence claims.

Pass gates:

- a clean-checkout rerun reproduces every claimed hash-bound result;
- the parsed schedule has 16 macro-stages, zero duplicate hand-coded source
  tables, and a corruption control that fails;
- geometry-first and entropy-first ratchets converge to the same survivor set
  and the same four-class count across seeds and candidate enumeration order;
- exact superoperator or Choi fingerprints accompany state-probe signatures;
- reverse-order, one-beat removal, duplicate-beat, sign-flip,
  terrain-identity, native-only, and non-native controls are all reported;
- each claimed load-bearing substage degrades a held-out task or object metric
  when removed or permuted;
- full-affine stage re-identification at least `0.95` over seeds;
- SVD-only proxy materially worse than the full affine representation;
- no mirror-pair conclusion from one seed;
- Type-2 order claim limited to the statistic that survives the multi-seed null.
- the sim-contract linter is clean for classification, manifest, depth,
  provenance, and result-shape requirements;
- PySINDy and every numerical dependency that changes an admitted metric are
  pinned and reproduced in the authority manifest.

Kill condition:

- if authority remains split across ambiguous checkouts, stop promotion until it is frozen;
- if the 64 count depends on repeated narrative labels instead of source-derived operator transitions, call it a 16-row object-card protocol rather than a 64-stage engine;
- if the two ratchets do not converge on four sequential, same-sign,
  load-bearing survivor classes, retain the one-step channel atlas and demote
  the four-substage engine interpretation;
- if full-affine identity falls near the proxy/null distribution, stop calling the 16 stages unique computational modes.

### WP1 - Object Contract And Battery

**Purpose:** replace authored loop labels with a real multi-view object problem.

Create:

- `system_v7/sims/qit_sme_object_battery_v0/`;
- versioned input fixtures and a sealed train/validation/test split;
- object cards containing candidate identity, measurements, provenance, contradictions, survivor hash, anti-hashes, and claim ceiling;
- view adapters that never expose the root object ID;
- collision, missing-view, wrong-site, wrong-time, and alias controls.

Pass gates:

- held-out object binding beats chance and non-engine baselines;
- removing order, provenance, or one load-bearing view degrades the declared metric;
- ambiguous collisions remain unresolved instead of being force-fit;
- object cards are stable under harmless vocabulary changes.

Kill condition:

- if a bag-of-fields or direct identifier baseline matches the engine path, the QIT object claim is demoted to ordinary entity resolution.

### WP2 - Type-1 / Type-2 Method Discriminator

**Purpose:** determine whether the two engine types do different useful work.

Run both methods over exactly the same held-out object trials:

```text
Type-1: candidate -> measurement -> prediction -> action/update -> falsifier -> receipt
Type-2: measurement -> candidate -> counter-projection -> action/update -> falsifier -> receipt
```

Required controls:

- order erased;
- engine sheet swapped;
- stage duplicated;
- one substage removed;
- static state only;
- shuffled context;
- view identity leaked and then explicitly rejected as an invalid control;
- action erased before the next observation;
- counterfactual world response held fixed despite different actions;
- declared regime shifts with Page-Hinkley and CUSUM detection windows.

Pass gates:

- each method has at least one preregistered task family where it significantly beats the other;
- differences persist across seeds and held-out objects;
- the winning behavior disappears under the relevant ablation;
- the same result is reproduced by the declared independent runtimes;
- actions causally change or select subsequent observations rather than only updating the next belief prediction;
- known regime shifts are detected within 8 ticks at the preregistered false-positive rate.

Kill condition:

- if method differences disappear after matching information and compute budgets, retain one engine and demote the two-type interpretation;
- if actions only update beliefs over a fixed fixture, retain the loop as a replay harness and withdraw the closed-engine claim;
- if declared shifts remain undetected, block adaptive-perception language until the detector is repaired.

### WP3 - Real PyTorch Learning

**Purpose:** make learning load-bearing without letting it become the judge of its own evidence.

PyTorch owns:

- differentiable feature learning or message passing;
- train-only optimization;
- calibration and uncertainty estimates;
- learned proposal ranking.

Julia owns:

- reference numerical arbitration for the frozen finite object;
- independent recomputation of admitted metrics.

JAX owns:

- seeded batch sweeps, null distributions, and robustness grids.

Pass gates:

- held-out improvement over frozen random features, majority class, linear bag-of-fields, and shuffled labels;
- no train/test object or alias leakage;
- calibration error and abstention quality reported;
- learned proposals cannot bypass deterministic object and host gates;
- removing the learned layer worsens the held-out metric.

Kill condition:

- if the learned layer only memorizes aliases or reproduces a simple baseline, keep PyTorch as a substrate but withdraw the learning-to-perceive claim.

### WP4 - Perception And Object Formation

**Purpose:** earn the phrase `AI can see an object` operationally.

Start with structured and text views. Add images only after the structured battery is sealed.

Required behavior:

- bind unseen views to a stable candidate object;
- maintain multiple hypotheses when evidence is insufficient;
- request a discriminating measurement;
- update or split an object when counter-evidence arrives;
- preserve the rejected projection as an anti-hash receipt;
- distinguish object persistence from vocabulary similarity.

Pass gates:

- novel-view recall and precision exceed preregistered floors;
- degeneracy refusal passes;
- adversarial jargon and synonym changes do not rewrite identity;
- a false convergence attack is detected;
- object formation improves a downstream maintenance decision.

Kill condition:

- if the system cannot outperform a modern entity-resolution baseline, call it a projection registry, not perception.

### WP5 - Lev Evidence Consumer

**Purpose:** make the runtime boundary real before allowing authority.

Implement in the current Lev architecture:

- a fresh adapter from the object receipt to `RunEvidence`;
- ProofBundle binding over source hashes, traces, gates, claims, and blocked consumers;
- durable idempotency key and replay test;
- `promotion_allowed=false` enforcement;
- explicit no-state-mutation test;
- k-of-n local verifier quorum over distinct evidence identities.

Pass gates:

- the same receipt consumed twice creates one evidence identity;
- tampering with any source, gate, or projection invalidates the bundle;
- failed or insufficient quorum cannot project;
- the consumer remains evidence-only by default;
- current Lev focused tests, typecheck, and relevant integration suite pass.

Kill condition:

- any path where external evidence mutates graph state before host policy and quorum is a release blocker.

### WP6 - Two-Node Mesh Trial

**Purpose:** test decentralized convergence without pretending the network is already sovereign.

Topology:

- two local Lev nodes with different partial views;
- each imports the other's data as claims/evidence, never direct state mutation;
- each computes local verification and anti-hashes;
- a reconciler emits convergence, conflict, or insufficient-evidence receipt.

Pass gates:

- message replay is idempotent;
- conflicting evidence does not silently converge;
- k-of-n decisions are deterministic from the same receipt set;
- partition/rejoin does not duplicate objects;
- no leader is required for evidence exchange, while host policy remains local.

Kill condition:

- if convergence depends on hidden shared mutable state, the mesh claim is withdrawn.

### WP7 - SME Utility Pilot

**Purpose:** prove business value rather than only internal elegance.

Pilot tasks:

- merge duplicate maintenance incidents;
- identify the likely asset and part family;
- expose conflicting safety or warranty constraints;
- recommend the next discriminating inspection;
- produce an auditable work-order evidence packet.

Pass gates:

- lower duplicate-work rate or time-to-resolution against the current workflow;
- every recommendation links to evidence and uncertainty;
- a domain expert can correct the object without losing provenance;
- tenant and company vocabularies remain scoped MMM projections rather than global truth.

Kill condition:

- no measurable workflow improvement after a fixed pilot budget means the architecture remains research, not a product system.

## Global Admission Rules

1. Builder output never admits itself.
2. Every positive has a mechanism-removing negative and a boundary case.
3. Every result names source hashes, command, runtime, seed, and claim ceiling.
4. No engine label may select a numeric constant or outcome.
5. No object ID, loop name, or view name may leak into model features.
6. Cross-runtime agreement is not scientific validity; it is implementation agreement.
7. Learning proposes; deterministic host gates decide.
8. Lev imports evidence before it imports state.
9. Mesh convergence requires explicit local policy and quorum.
10. A failed gate remains a first-class research result.
11. Narrative science phases and source-derived operator substages are separate contracts until a parser proves they coincide.
