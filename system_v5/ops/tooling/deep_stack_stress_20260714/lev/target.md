Deep-stress each finite-roster tool or library through its correct runtime and
real API. Every required member must carry positive, negative, boundary,
stress, demotion, adjacency-witness, representative-sim, and qualified-call
evidence. The estate must contain exactly the 139 registry members and every
declared adjacency witness, with no duplicates, extras, or omissions. This
final suite additionally requires all 95 deep-stress receipts and all 29
adjacency witnesses to pass operationally in a fresh, run-scoped estate with no
raw reuse. The 29 receipts must remain literally classified as 25 member
co-health compatibility witnesses, three independent shared cross-checks, and
one direct value handoff.
The required-operational-bucket subset is exactly 86 of those 95 rows; the
remaining nine are operational legacy rows whose system membership stays
unclassified. All 44 policy-only rows must also remain policy-green.

Freshness is byte-bound, not asserted in prose: each of the seven raw roles
must have exactly one successful producer command bound to the same run-scoped
output path and SHA-256, after explicit deletion of any preexisting output.
Every parent command must be an executed command record and none may carry a
reused-raw marker or `--reuse-raw` argument. Every operational command and
representative consumer must exit zero; a scientific-red payload never excuses
an API or process failure.

Representative-consumer evidence is also execution-bound. All 95 deep rows
must preserve an executed command, exit and timeout state, exact declared
output-contract paths, freshly recreated emitted-artifact hashes, an empty
API-failure scan, and the invoked live source plus preserved execution-copy
hashes for their declared consumer. Any temporary root rewrite must be declared
and confined to the disposable projection; together the receipts must cover
the registry's exact 48 unique representative sources. File
existence plus an unrelated fixture pass is not representative execution, and
representative execution never replaces the positive, negative, boundary,
stress, demotion, or adjacent-integration cases.

Shared consumer execution is not enough by itself. A source mapped to one tool
must bind the registry row, invoked source, and exact fresh-output contract. A
source mapped to multiple tools must additionally name each tool through an
exact structured artifact identity derived from declared package/tool fields;
free-text and substring token matches do not count. This mapping remains
representative-consumer evidence only; the raw four-case probe is still the
load-bearing API evidence.

This lane is local, no-install, network-denied, and model-free. It must not use
the Claude bridge, Claude or Anthropic adapters, provider calls, or frozen
provider prose as execution evidence. The canonical Python runtime drives the
parent runner; that runner owns the strict Julia and isolated-runtime bindings.

The independent validator remains red-capable: an honest operational red can be
a structurally valid diagnostic receipt, and its selftest preserves that
fail-closed distinction. A red row may not be hidden, promoted, or converted
into process green. This final Lev suite deliberately adds the stricter
`--require-operational-pass` gate plus exact-count assertions, so any red among
the 95 deep-stress tools or 29 adjacency witnesses blocks this campaign run.

Lev's result is projection-only and release-ineligible. Tool integration
diagnostics do not prove Ratchet mechanics, QIT semantics, or any scientific
claim.
