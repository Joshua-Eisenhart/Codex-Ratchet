# Three-Wave Council Primer

Status: proposal / salience-probe stage. This file does not replace active Wizard runtime law.

## Purpose

Receipt rules bind; MMMs and mini-MMMs lift.

The hardened Wizard spine is three sequential councils:

1. Decision Council.
2. Failure Council.
3. Follow-up Council.

The councils are sequential write barriers. Parallelism happens inside each wave, not between waves.

## MMM Boundary

MMMs and mini-MMMs are positive salience manifolds. They are not rules, deterministic gates, glossaries, or negative law banks. They bias the context window toward project-native words, phraselets, cadence, and grammar so system-native continuations become more likely.

The existing v3.4 MMMs and mini-MMMs were mined from the wiki and are assumed to be broadly aligned to Joshua's system unless a specific drift probe shows otherwise. In the three-wave Wizard, they are salience surfaces loaded to shape council roles, not compliance contracts.

The active Wizard packet still owns route execution, receipt accounting, and runtime authority. The MMM layer owns salience pressure: increasing the use and availability of words such as candidate, probe, survivor, constraint, admissible, excluded, receipt, rung, open, held, and bounded.

## Wiki / Harness / Memory Reservoir

The wiki is the living upstream reservoir for the system. The Wizard harness, consolidated harness, concepts, Codex memory, Claude memory, and Hermes memory surfaces are not peripheral notes; they are the corpus that keeps the salience field current.

The three-wave Wizard treats these surfaces differently:

- `wiki/wizard/` and `wiki/wizard/harness-consolidated/` provide active harness and salience doctrine.
- `wiki/codex-memory/` preserves Codex-owned context and user corrections.
- `wiki/claude-memory/` preserves Claude-owned session memory.
- `wiki/hermes-current/` preserves Hermes-owned operating memory and carry-forward packets.

The wiki is a shared reservoir. Runtime-specific memory directories remain single-writer surfaces unless an explicit import/admission step says otherwise.

MMM refresh is not "rewrite rules." It is re-mining and re-weighting the language field from the current wiki, including harness drift probes, user corrections, and cross-runtime memory packets.

Track three axes separately:

- `load_axis`: whether a surface exists and was actually loaded.
- `salience_axis`: whether it shifts vocabulary, phraselets, cadence, grammar, and framing toward the intended attractor.
- `counter_probe_axis`: whether that shift survives rationalist/default-model pull.

A surface can load correctly while showing no lift. It can show vocabulary lift while folding under counter-probe. These are different findings.

## Wave 1: Decision Council

Use: bias the worker toward choosing the best bounded move now while preserving live alternatives and evidence status.

Internal roles may draw from Hume, Zhuangzi, Strategy, Factory, Systems, Direct, Alternative, and Reframe salience.

Return:

- selected move;
- one or two live alternatives;
- raw receipt references;
- evidence boundary;
- accepted risks;
- risky claims for Failure Council;
- falsifier seed.

Avoid:

- full failure analysis;
- lane catalog output;
- generic Six Hats balance with no project-native receipt pressure;
- restoring legacy voice routes as quotas.

## Wave 2: Failure Council

Use: bias the worker toward failure pressure: killed/open/survived, hidden assumptions, countermodels, and early warning surfaces.

Failure Council reads Decision Council raw receipts, not only Decision synthesis.

Internal roles may draw from Popper, Feynman, Pushback, Audit, Security, Systems, Factory, premortem, and future-postmortem salience.

Return:

- verdict: `kill`, `quarantine`, `harden`, or `pass`;
- target claim;
- strongest falsifier;
- decisive check;
- hidden assumption;
- required hardening;
- early warnings;
- whether control returns to Decision Council.

Avoid:

- adjectives instead of verdicts;
- turning unsupported decisions into follow-up prompts;
- sharing the same inhabited register as audit;
- Hume/Zhuangzi-style softening when a verdict is required.

## Wave 3: Follow-up Council

Use: bias the worker toward divergent next moves after the Failure verdict, then select executable options.

Internal roles may draw from Direct, Alternative, Reframe, Back, Wildcard, All-A, All-B, All-C, Full Wizard, Factory, Strategy, Orwell, Hygiene, Audit, and Security.

Return visible options only when each option has:

- target artifact or surface;
- owner/agent shape;
- check or done condition;
- payoff;
- use-when condition;
- defer/block condition;
- scout status.

Avoid:

- prompt theater;
- "preworked" claims without Make, Scout, and Audit receipts;
- reopening failure analysis unless Failure Council explicitly returns control;
- Full Wizard as an all-routes quota.

## Liveness / Rerouter

The liveness role lives inside each wave. It is not a fourth council.

It tracks:

- spawned;
- completed;
- accepted canonical;
- superseded;
- late;
- blocked;
- deferred;
- simulated.

Reroute only on explicit terminal reasons: timeout, blocked dependency, malformed receipt, wrong source slice, or no progress by deadline. Reroute smaller, not broader.

## Salience Probe

A council-role salience surface earns stronger status when it measurably shifts vocabulary, framing, and route salience in the intended direction; status decays when it stops doing so. The expected signal is gradient shift, not deterministic compliance.

Each salience surface should make the following continuations easier than default-model drift:

1. Project-native nouns and verbs appear without being forced into labels.
2. Default completion basins such as winner-story, causal-story smoothing, role cosplay, and unreceipted authority become less likely.
3. Constraint, evidence boundary, survivor/open status, and excluded inference become natural sentence shapes.
4. Role-local salience differs by council role without requiring deterministic outputs.
5. Label-stripped outputs still show the same orientation toward bounded evidence and live alternatives.
6. Existing MMM/mini-MMM material remains a positive salience reservoir and is not rewritten into rule lists.
7. Repeated use reinforces the system vocabulary rather than merely decorating output.

Measure salience lift with continuous probes: correction frequency, drift resistance, completion stems, vocabulary/grammar pull, native-term density, and whether outputs preserve system distinctions more often than the no-MMM baseline.

When salience-lift and receipt truth disagree, receipt truth wins for execution claims. The disagreement is logged as a salience-drift signal instead of being smoothed.

Watch for fake lift: vocabulary penetration without changed reasoning moves. A label-stripped or plain-English paraphrase should still preserve the same bounded evidence stance, live alternatives, and status distinctions.
