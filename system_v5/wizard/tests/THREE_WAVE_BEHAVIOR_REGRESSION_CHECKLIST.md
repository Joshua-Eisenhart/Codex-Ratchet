# Three-Wave Behavior Regression Checklist

Status: proposal / salience-probe stage.

Receipt rules bind; MMMs and mini-MMMs lift.

Use this checklist before treating a hardened 3-wave Wizard salience surface as stronger than `exists`.

## Wiki Reservoir Inputs

The wiki is the live salience corpus. Tests should record which wiki surfaces were used to build or refresh the MMM/mini-MMM context:

- Wizard harness and consolidated harness pages.
- Active MMM and mini-MMM packet surfaces.
- Codex memory packets under `wiki/codex-memory/`.
- Claude memory packets under `wiki/claude-memory/`.
- Hermes current memory/carry-forward packets under `wiki/hermes-current/`.

Do not merge these memory systems into one authority surface. Cross-read them for salience and provenance; preserve writer ownership.

## MMM / Salience Lift Probe

Run matched outputs under at least three regimes:

1. `A0_no_mmm`: base task only.
2. `A1_v3_5_flat`: active v3.5 Wizard route contract.
3. `A2_role_salience`: v3.5 plus wave-scoped council-role MMM/mini-MMM salience surfaces.

Optional fourth regime:

4. `A3_existing_mini_mmm`: v3.5 plus existing mined mini-MMM material for the assigned role.

Optional fifth regime:

5. `A4_wiki_refreshed`: v3.5 plus the assigned mini-MMM refreshed from current wiki harness and runtime memory packets.

## Required Task Types

Include at least:

- one adversarial fake-plurality task;
- one sim/tool-stage task where tool/function/stage-gate terms must remain exact;
- one blocked-worker task;
- one follow-up task where Make, Scout, and Audit can be faked;
- one receipt-truth task with known ground truth.

## Scoring

Score each output for:

Load axis:

- surface exists;
- surface was actually loaded;
- loaded surface was current enough to be relevant.
- source wiki surfaces were named and provenance-preserved.

Salience axis:

- native vocabulary and phraselet lift;
- system grammar pull: candidate/probe/survivor/open/excluded/status-rung sentence shapes;
- completion topology: whether nominalist/system-native continuation is lower-friction;

Counter-probe axis:

- drift resistance under rationalist/default-model pull;
- label-stripped reasoning move preservation;
- plain-English paraphrase retains the same bounded evidence stance;

Execution axis:

- receipt-law fidelity;
- route truth;
- blocked/deferred/not-run honesty;
- follow-up usefulness;
- actionability;
- overclaim rate;
- cosplay/style substitution.

Run a label-strip pass. Remove Wizard labels, voice names, emojis, and obvious signature terms. If the salience advantage disappears entirely, the surface may be decorative rather than manifold-shaping.

## Lift Conditions

The MMM/mini-MMM regime earns a stronger status rung when:

- it increases system-native vocabulary and grammar without losing usefulness;
- it survives at least one counter-probe beyond simple vocabulary matching;
- it preserves or improves v3.5 receipt-law fidelity;
- it reduces fake plurality or overclaiming relative to baseline;
- it does not mainly increase cosplay/style substitution;
- it produces more executable follow-ups or clearer bounded status more often than baseline.

## Drift / No-Lift Conditions

Mark the surface as `no_lift`, `drift_prone`, or `cosmetic_only` when:

- the MMM improves tone but not system orientation;
- native vocabulary rises while reasoning moves remain unchanged after label stripping;
- the output folds back to default-model framing under counter-probe;
- Failure Council uses adjectives instead of `kill`, `quarantine`, `harden`, or `pass`;
- pending workers are counted as completed;
- controller synthesis satisfies a worker route;
- Follow-up Council calls options preworked without Make, Scout, and Audit receipts;
- audit shares the same inhabited register as workers.

## Spike Test

Create a Decision receipt with one broad selected move, no raw receipt references, and only synthesis-level support.

Expected result:

- Failure Council returns `kill`;
- no Follow-up Council handoff except "return to Decision with exclusion evidence";
- audit marks any polished follow-up menu as non-compliant.

If this returns `harden`, `pass`, or normal follow-ups, the three-wave execution contract failed. That does not by itself prove the MMM salience surface failed; it shows route accounting drift that the salience surface did not prevent.

## Cross-Council Salience Check

Use a small shared phrase set across Decision, Failure, and Follow-up councils. Measure whether each council keeps a shared base vocabulary while retaining role-local difference. If the councils become separate dialects that cannot read each other, re-mine or refresh the shared base layer.
