## A. Five Circularity Species

Each audit verdict must name these species exactly when they appear. A species finding is evidence hygiene, not automatic rejection unless the result depends on the circular path.

| Species | Canonical definition | Source evidence | Rule | Rationale |
|---|---|---|---|---|
| `frozen-factor echo` | A count or class appears because a frozen complementary factor is projected back as if it were moving-object structure. | `f8533d772`, `owner_prediction_64_subsubbasins_20260611.md:159-174`: one-sided 32 was the frozen complementary engine state count, not 32 moving-engine subsubbasins. | Cite only as a factor echo unless a same-object moving dynamics row computes the structure. | Prevents frozen-product artifacts from becoming basin/subbasin claims. |
| `definitional circularity` | The result is forced by the implementation definition, so the advertised falsifier is analytically unreachable. | `28fc221a1`, `owner_doctrine_cellular_automata_ring_checkerboard_20260611.md:66-83`: period-2-vs-4 was definitionally forced by two phase updates vs one. | Demote the forced row to implementation-correctness; preserve any independently varying structural row. | Separates discovered structure from values baked into the rule. |
| `rule-table readback` | A claimed invariant is a rule-table parameter read back from metadata instead of computed from realized operators/objects. | `88b5e9ff1`, `owner_doctrine_cellular_automata_ring_checkerboard_20260611.md:87-94`: QCA v1 index was a rule-table flow parameter read back. | A rule-table parameter cannot be cited as an invariant; the invariant must be recomputed from realized finite support/algebra/overlap data with controls that could fail. | Blocks metadata from masquerading as computation. |
| `post-hoc statistic` | A statistic scores targets selected from the observed positive rows rather than from an independent predeclared target set. | `02d7d9fc6`, `spinor_network_surface_v2/audit_verdict.md:13-21,66-81,152-160`: family-tied target cells were the observed Haar-positive cells, with no independent required-pair set. | Significant-looking statistics bind only when target set, seeds or prediction family, null, and scoring rule are predeclared before result inspection. | Preserves falsifiability of statistical evidence. |
| `shift-relabeling` | Calibration or shift rows are relabeled as the target engine/object rows without distinct target realization. | `315ac529c`, `owner_doctrine_cellular_automata_ring_checkerboard_20260611.md:114-122`: QCA v2 engine rows were calibration shifts relabeled, not distinct engine operators. | Calibration rows are controls; a target row numerically equal to a calibration row self-rejects unless distinct source-pinned target operators were built first. | Keeps calibration from becoming the claim. |

## B. G7 Pin Rule And Enumerate-Subvariants Resolution

**G7 quoted rule.** Source commit: `b6fafc67f` lineage via `axis6_contender_probe_registry_20260612.md:144-146`.

> `adapter_pin`: the G7 rule is binding. Every adapter realization must be pinned by rule, source path, convention tuple, and hash or finite row list before evaluation.

Rationale: the builder cannot choose the adapter after seeing the answer.

**Enumeration quoted rule.** Source commit: `c27d3dd39`, `axis0_contender_heavy_v0/build_card.md:11`.

> The G7 lesson binds: every adapter realization choice is pinned before computation; where the registry map underdetermines a detail, enumerate minimal subvariants.

Rationale: underdetermination is handled by bounded finite enumeration, not builder discretion.

**Conflict resolution.** Source: `/tmp/fable_audit_findings.json`, standards-coherence kill row; source evidence: `axis0_contender_heavy_v0/audit_verdict.md:58-69`.

G7 governs **what** must be pinned. Enumerate-subvariants governs **how** an underdetermined pin is made finite. The enumeration boundary must be a closed finite list in the pre-registered registry or build card before any sim runs. After results are inspected, no new subvariant may enter the adjudicated set. If a needed positive predicate or subvariant appears only as an audit-time correction, the packet may be `PASS_WITH_CAVEATS` but must carry a post-hoc standards-gap caveat.

Rationale: this preserves useful enumeration while preventing in-compute discovery from becoming pinning.

## C. No-Identity-Leak Standard

Source commit: `b6fafc67f`.

Definition: a claimed independence or contender row passes the no-identity-leak standard only if the claimed value is not recoverable with majority accuracy `1.0` from cell identity, coordinate tuple, direct output fingerprint, or any equivalent row identifier. Identity-inclusive predictors may be reported, but they do not count toward the pass/fail independence predictor.

Source evidence:

- `discrete_axis6_precedence_v0/audit_verdict.md:48-59`: identity-inclusive recovery is `1.0`, and future citations must state the exclusion.
- `discrete_axis6_precedence_v0_common.py:591-602`: result rows emit `identity_leak_detected`, `identity_leak_exclusion_rule`, and `identity_leak_excluded_best_accuracy`.
- `validate_discrete_axis6_precedence_v0.py:121-124`: validator requires the identity-leak caveat and non-identity accuracy `< 1.0`.

Operational test:

1. Run identity-inclusive recovery using cell id, coordinates, direct fingerprints, and equivalent identity keys.
2. Run the best non-identity predictor after excluding those fields.
3. A claimed independence row may pass only if the identity-inclusive leak is reported and the identity-excluded best accuracy is `< 1.0`.

Required result fields for every independence/contender packet:

- `identity_leak_detected`
- `identity_leak_excluded_best_accuracy`
- `identity_leak_exclusion_rule`

Citation duty: every citation of a no-identity-leak result must say whether identity leakage was detected, which identity fields were excluded, and what the best identity-excluded predictor accuracy was.

Rationale: probe-relative identity cannot be tested by leaking the probe row's name back into the predictor.

## E. Freshness Tiers

Source commits: `bd280334b`, `00f66b9a6`, and Fable standards lens.

Source evidence:

- `audit_bar_calibration_20260610.md:5`: fresh-context audits are kept as constraint-grounded.
- `post_demotion_sweep_audit_20260611.md:20-28`: freshness can be checked by diff tracing, scratch reruns, and no-write hygiene.

Rules:

| Tier | Name | Definition | Required when | Rationale |
|---|---|---|---|---|
| `TIER-1` | full-blind | Auditor has no prior result or verdict exposure; independent context/model where feasible; recomputes from source/card, not result prose. | Contested packets, canonical/promotion candidates, bridge/physics/manifold-adjacent claims, and any packet with a kill-row history. | Needed when prior exposure could steer interpretation. |
| `TIER-2` | results-available | Auditor may read result JSON/source and build card, but not prior audit verdicts or summaries before recomputation. | Routine fresh audits of scratch packets and hardening reruns. | Allows practical verification without inherited verdict language. |
| `TIER-3` | annotation-verify | Prior verdict or audit prose is accessible; auditor must list contaminated inputs and mark which rows were independently recomputed. | Re-audits, drift checks, status repairs, and post-demotion sweeps. | Useful for maintenance, but it cannot be sold as blind. |

Every audit verdict must state its freshness tier.

Rationale: "fresh" is otherwise non-uniform and cannot be checked.

## F. Pre-Registration Evidence Rules

Source commits: `00d784ceb`, `287084d80`, `bd280334b`.

Rules:

1. A blind value is evidence for a packet only when the packet independently recomputes the same value through its own source path.
   - Source: `cross_model_anchor_recompute_panel3_20260610.md:9,25`.
   - Rationale: the panel is pre-registration pressure, not the computation.
2. A panel miss is a `FINDING-TO-RECONCILE`, not an automatic fail.
   - Source: `audit_bar_calibration_20260610.md:9`; `mct_advisory_crosscheck_20260610.md:111-113`.
   - Rationale: a miss can expose blind-sheet arithmetic error, prompt contamination, method mismatch, or packet failure; the reconciliation path decides.
3. A panel with fewer than three independent routes is advisory-only unless a later packet recomputes the value.
   - Source: `cross_model_anchor_recompute_panel3_20260610.md:3-9,23-25`.
   - Rationale: unanimity helps, but process authority still requires packet-local computation.
4. Never tune to panel.
   - Source: `cross_model_anchor_recompute_panel3_20260610.md:9,25`.
   - Rationale: "must earn by computation" forbids copying expected values into source or tuning choices to match a known panel.
5. The packet source must contain the derivation or computation path; a reference to the blind sheet is not enough.
   - Source: `mct_advisory_crosscheck_20260610.md:96-113`.
   - Rationale: direct numerical or symbolic verification is the reconciliation surface.

## G. File/Builder Boundaries And Post-Audit Idempotency

Source commits: `f1907c814`, `00f66b9a6`.

Rules:

1. Builder file boundary: a build card must list allowed writes, and a builder must not write `audit_verdict.md`.
   - Source: `system_v5/codex_skills/sim-wizard/SKILL.md:17-37,65-79` at `f1907c814`.
   - Rationale: builder output and independent audit output must stay separable.
2. Post-audit idempotency: validators must assert the build-time envelope field `no_builder_audit_verdict`, not require `audit_verdict.md` absence forever after a legitimate audit exists.
   - Source: `f1907c814` commit message and validator calls to `builder_audit_boundary_errors(...)`.
   - Rationale: a genuine audit must not break its own packet validator.
3. Independent audit header gate: if `audit_verdict.md` exists, the validator may accept it only when its header declares independent/fresh/read-only audit status.
   - Source: `scripts/builder_audit_boundary.py:21-66`.
   - Rationale: post-audit idempotency is not permission for builder-authored verdicts.
4. Scratch-clone reruns are allowed only for freshness verification.
   - Source: `post_demotion_sweep_audit_20260611.md:20-28,41-54`.
   - Rationale: `/tmp` execution can verify but does not write promotion-eligible live artifacts.
2a. Idempotency-from-birth (added 2026-06-12): NEW packet validators and tests must delegate the
   `audit_verdict.md` check to `scripts/builder_audit_boundary.py` from the first build — never a
   hard absence assertion. Build cards should state this; auditors flag any new hard absence check
   as a contract violation, not a post-hoc fix item.
   - Source: three identical post-audit fixes in one session (`189776c36`, `290c89b70`, `1f4ddfb1e`)
     all tracing to builders templating the old absence check from pre-`f1907c814` packets.
   - Rationale: rule 2 keeps being violated at birth because the broken pattern propagates by
     copy-paste; the fix belongs in the build contract, not in a recurring repair lane.
5. If scratch-clone results differ from committed live results, write a named discrepancy record before citing the live result as passing.
   - Source: `post_demotion_sweep_audit_20260611.md:20-28`.
   - Rationale: scratch divergence is evidence, not cleanup.

## H. Corrected Vocabularies

Source commits: `a3a6daeb6`, `fe09e11cb`, `c27d3dd39`, `1ee413779`.

Rules:

1. `open + queued-heavy` / `open + queued-heavy-local`
   - Source: `axis0_contender_sweep_v0/audit_verdict.md:3-13,76-103`; `round3_s4_alias_pass_v0/audit_verdict.md:23-30,90-104,122-126`.
   - Rule: not-run heavy rows are not known co-survivors. They are open and queued until their named heavy teeth run or a prior co-survivor receipt is cited.
   - Rationale: queue status is not survivor evidence.
2. Co-survivor citation duty
   - Source: `round3_s4_alias_pass_v0/audit_verdict.md:101-104`.
   - Rule: a co-survivor citation must name the prior receipt and the exact teeth that made it a co-survivor; otherwise cite `open + queued`.
   - Rationale: prevents "co-survivor-open" from sounding like a result.
3. Convention-pinned reopenable
   - Source: `round3_s4_alias_pass_v0/audit_verdict.md:19-22,180-188`.
   - Rule: an exclusion under a pinned convention is valid only under that convention; relaxing the pin reopens the row as a convention-relative alias/neighbor question.
   - Rationale: convention-relative negatives must not become intrinsic kills.
4. Claim-bearing vocabulary gate
   - Source: `CLAUDE.md:7-15,141-146` as reference doctrine under `AGENTS.md`.
   - Rule: claim-bearing result fields and verdict prose must prefer `survived`, `admitted`, `excluded`, `indistinguishable`, `co-varies under`, `UNSAT under`, `stable under probe`, and related constraint vocabulary. Banned causal/classical verbs in claim-bearing fields are findings with severity proportional to the claim.
   - Rationale: wording must preserve the root axiom's probe-relative evidence ceiling.
