## Fable pressure: live readings to preserve

**Qubit-ladder-per-level (do not crown 8Q or 5Q):**
1. *Capacity reading* — n indexes carrier resources only (Cl(2n), max family 2n+1); terrains and stages are readout structure laid over whatever carrier exists. The ladder spec's resource table supports this reading directly; the floor stays 3Q regardless of n.
2. *Seat-register reading* (the owner's "8 stages → 8 qubits") — each engine stage is one physical qubit, so the 8-stage engine wants an 8-qubit register and the 16 placements want 16 (or 8 qubits × 2 signs). Nothing on disk yet earns or kills this; n=5 hasn't even run.
3. *Address reading* — 8 terrains need only 3 qubits (2³ = 8 addresses) if terrain identity is a label, vs 8 qubits one-hot if each terrain realization must carry its own Bloch shell `z=cos(2η)` independently. These give different minimum registers (3 vs 8) and different leakage tables; the divergence is real and currently untested.
4. *Boundary-beyond-floor* — the spec already contains a natural boundary discriminator: max family 17 at n=8, next family needs dimension 512. "Boundary testing beyond floor" can mean probing where the n=8 row fails upward, without moving the 3Q floor.

**720 loop / linear engine — three separated readings, one falsifier each:**
- *Bus reading*: the 4π spinor loop is a shared transport bus; 8-16 qubit states are carried through one double-cover loop coordinate, and "linear/efficient" means one bus pass instead of per-qubit machinery. **Falsifier/control**: swap the 4π double-cover loop for the 2π SO(3)/vector loop on the same multi-qubit readout (the exact control family `geo_s1_vector_vs_spinor_v0` already built at 1Q). If the multi-qubit observable is unchanged, the bus is decorative.
- *Schedule reading*: the loop is a time order, not a place — the engine "runs qubits through" the loop by sequencing stage operators (`Phi_D=UEUE` vs `Phi_I=EUEU`, S6), and 720° means the schedule must traverse the placement set twice before closing. **Falsifier/control**: commuting-generator control — run the same schedule with generators forced to commute; if the order gap `Delta_{T,O}` persists, the schedule reading is an artifact; if it vanishes only there, order is load-bearing.
- *Seat-register reading*: each stage/placement is a qubit pinned at a fixed loop angle; one 720° traversal visits each seat twice with opposite sign — exactly the Möbius identification `(theta,s)~(theta+2pi,-s)`, which is why 8 seats × 2 signs = 16 placements. **Falsifier/control**: duplicate-eta / collapsed-shell controls (already named in the n=4 mutation-control set) — collapse all seats to one coordinate; if the engine readout survives, seats are labels, not carriers. Note this reading leans on machinery the program explicitly defers behind S1-S7; preserving the reading does not un-defer the automaton.
