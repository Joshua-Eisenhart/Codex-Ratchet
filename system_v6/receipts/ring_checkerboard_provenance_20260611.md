    if seed_center: row[N//2]=1

The owner-source ring-checkerboard support can be realized as a classical partitioned finite automaton whose two-phase local update expresses:

- deductive loop order as the alternating checkerboard phase;

### Partitioned Update

Phase A:

```text
deductive/checkerboard phase:
  use C_D = Se -> Ne -> Ni -> Si
  readout periodicity must be alternating
  update only admissible kappa/parity class or declared phase partition
```

Phase B:

```text
inductive/paired phase:
  use C_I = Se -> Si -> Ni -> Ne
  readout periodicity must be paired
  update paired/block cells that correspond to owner-source ring steps / engine stages
```

The phrase `B order constraints` is interpreted here as binding constraints on the B phase/order row: B must preserve inductive paired order and must not silently use the deductive alternating order. If the project has a more specific `B` convention row, that row must be loaded before build.

### Phase Tests

Positive:

- deductive phase emits alternating period-2 readout for both engine types, with casing/placement differences only;
- inductive phase emits paired period-4 readout for both engine types;
- ring-step ladder rows remain finite and typed;
- inner/outer inversion is present as a placement/readout row, not as a quantum chirality proof.

Negative / controls:

- non-partitioned scramble control: update all cells with a global shuffled rule; must destroy the alternating/paired phase signature or mark the signature non-load-bearing;
- order-shuffle control: preserve counts but shuffle `C_D` / `C_I`; must break the specific alternating/paired association;
- label-shuffle control: relabel vertices while preserving graph structure; structural results should survive;
- ring-off control: remove ring edges; basin/phase result should change if ring structure is load-bearing;
- checkerboard-off control: erase `kappa`; parity/phase result should be unavailable or fail;
- nesting-off control: erase radial nesting; nested-ring presentation row must fail or demote;
- generic CA baseline: elementary rule baseline may run, but only as contrast. It cannot stand in for the owner's structure.
