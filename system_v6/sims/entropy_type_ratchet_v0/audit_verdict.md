## Findings

G1. **Premature evaluation is a real exception path but not an object-construction proof.** `evaluate_type()` calls `require_structures()` and raises `MissingStructure:density_quotient_rho`, `MissingStructure:bipartition_subsystem_split`, or `MissingStructure:channel_update_map` before computing vN, `S(A|B)`, or `I_c`. That is better than returning sentinel numbers. But the absence/presence of those structures comes from the local `enabled` set accumulated from `PRIMARY_STEP_PLAN`, so the failure is a declared-availability gate, not a failed attempt to construct `rho`, a bipartition, or a channel from the consumed sequence.

G2. **Computed values checked, but several are local fixtures.** I independently recomputed `log(8) = 2.0794415416798357` for the seed counting entropy and `-sum([0.5,0.5] * log([0.5,0.5])) = log(2) = 0.6931471805599453` for the quotient-step vN value. Both match the packet. The vN row, however, uses a local constant `rho_diag = [0.5, 0.5]`; it is not derived from the lens quotient object.

G3. **Controls are mostly honest, but not doctrine-complete.** The product-state conditional row is computed and flagged `degenerate` at `terrain_restriction`. The in-packet typed ledger genuinely rejects a cross-type sum, raising `cross_type_sum_rejected:finite_counting_entropy_nats+von_neumann_entropy_nats`.

G4. **SMT is not fabricated, but the table proof is only as strong as the declared table generator.** JAX `z3` and `cvc5` bind variables to the computed status-code table and make a mismatch UNSAT; the perturbed `2_von_neumann_entropy` entry is SAT. That perturbation flows through solver assertions, not through a recomputed construction pipeline. Julia Z3 is weaker: `final_count = 6` is hardcoded before proof, so it is not a table-binding witness.

G5. **Tool honesty needs demotion.** `QuantumOptics` is load-bearing for the local `rho` and Bell entropy numeric checks, not for the availability schedule. `z3`/`cvc5` are load-bearing for internal table-consistency checks, not for source-derived enabling-layer discovery. `torch_geometric`, `torch.func`, and PyTorch are mirrors/boundary checks and should be treated as supportive for the doctrine claim; the graph degree mirrors the table, and the autograd scale derivative does not decide co-ratchet admissibility.
