## Verdict Teeth

### 1. Group size and generators

Accepted with a wording caveat.

The packet's `|G|=256` is correct for the address group generated by the six line flips plus reversal plus trigram swap. The decomposition is:

```text
translation subgroup from six flips = (Z_2)^6, order 64
linear coordinate subgroup from reversal and trigram swap = V_4, order 4
total generated affine/address group = 64 * 4 = 256
```

Complement is redundant: the all-ones complement is already in the flip subgroup, and adding it to flips+reversal+trigram swap does not increase the group size. This is not a fatal issue because the recomputed group size did not double-count it, but the packet should state the redundancy explicitly in future result prose. The emitted result reports `hex_group_size=256`, `engine_group_size=256`, and conjugated equality at `results/iching_symmetry_match_v0_results.json:939-945`; source construction includes flips, complement, reversal, and trigram swap at `iching_symmetry_match_v0.py:427-453`.

### 2. Isomorphism strength

Accepted precisely as **address-level group action isomorphism / equivariant bijection**, not merely abstract `2^k` group isomorphism.

The recompute found:

```text
hex_group=256
engine_group=256
conjugated_equal=True
all_generator_hom_rows_pass=True
```

So for the generated address actions, `phi(g.h) = psi(g).phi(h)` holds and conjugates the generated hexagram permutation group to the generated engine permutation group. This is stronger than an abstract group isomorphism.

Caveat: the non-flip engine generators are induced through `phi` by construction (`iching_symmetry_match_v0.py:436-443`), so this is an address/schedule-index equivariance result. It is not independent evidence that the engine behavior has the same 256-action symmetry.
