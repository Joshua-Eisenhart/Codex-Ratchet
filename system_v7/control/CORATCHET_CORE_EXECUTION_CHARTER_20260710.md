# Co-Ratchet Core Execution Charter - 2026-07-10

Status: owner-aligned execution proposal, not Ratchet canon.

This charter exists because prior work repeatedly promoted source architecture,
standard mathematics, installed implementation choices, and green diagnostics
into one undifferentiated `canon`. It also tested closed engine loops as linear
operator orders and tested downstream stage machinery before the recursive
co-ratchet core existed.

## Owner Architecture Being Built

- One recursive QIT entropy/geometry co-ratchet is the core engine process.
- There are 16 intelligence-bearing stages total.
- Each stage is intended to perform a distinct kind of intelligent work.
- A stage may internally process through four substages.
- Internal substages form a closed loop with no privileged first or last
  position. Linear Ti/Te/Fi/Fe chains are not source schedules.
- All internal positions of one stage inherit that stage's single Axis-6
  precedence sign.
- Type 1 and Type 2 are mirrored deductive/inductive organizations of loops,
  not different linear operator permutations.
- `16 x 4 = 64` is only a provisional execution grid. It is not 64 stages or
  64 intelligences.

This owner specification is binding for implementation fidelity. It does not
by itself prove that four substages are mathematically forced.

## The Actual Co-Ratchet

Let `S_n` be current finite support, `P_n` the admitted probes, `Q_n` the probe
quotient, `D_n` unresolved distinguishability demands, and `W_n` the append-only
witness ledger.

### 1. Primal survivor ratchet

```text
Q_n = S_n / ~_{P_n}
D_n = required distinctions not carried by Q_n
```

Enumerate the weakest candidate probes, transformations, relations, or lifts
that could close at least one demand. Do not choose a unique minimum when
several candidates are incomparable.

### 2. Geometry face

For every candidate, derive only the geometry licensed by `Q_n`: adjacency,
incidence, reachability, partition/refinement, and later a metric or connection
only when a weaker relation cannot carry a required distinction.

The geometry gate asks:

```text
Does this candidate preserve the admitted witnesses and close a demand?
Can a strictly weaker geometry do the same work?
Does geometry survive relabeling and representation controls?
```

### 3. Operator/entropy face

Use only entropy/readout families licensed by the current structure:

- support/quotient/block counts before probability;
- Shannon quantities only after a probability measure;
- spectral/von-Neumann quantities only after a density/operator state is
  independently admitted;
- GNS and modular operators only after the state and positive algebra exist;
- relative-entropy/DPI pawls only for declared map classes.

The entropy/operator gate asks:

```text
What distinction is preserved, erased, or still unresolved?
Is the proposed pawl monotone under every admitted map in its scope?
Does an erased/wrong-pawl control flip?
```

### 4. Bidirectional co-ratchet

Run both compositions over the same candidate ledger:

```text
S_EG = E(G(candidates))
S_GE = G(E(candidates))
S_*  = stable equivalence classes in S_EG intersect S_GE
```

Do not require equality of intermediate paths. Record where E→G and G→E bind
different structure. Admit only the common minimal survivor classes whose
differences are representation-independent and load-bearing.

### 5. Return to foundations

This is the step missing from most current simulations:

```text
admitted survivor
-> update support/probes/witnesses
-> recompute quotient from raw finite support
-> recompute licensed geometry from the new quotient
-> recompute licensed operator/entropy faces
-> generate the next unresolved demand
-> rerun MSS from the foundation
```

No derived metric, cluster, terrain, or stage label may be carried forward as
an unquestioned primitive. Only its receipt and recreatable construction may be
carried.

### 6. Stop conditions

The run stops at the first of:

- no unresolved demand;
- no admissible candidate closes a demand;
- a hash-identical fixed point;
- a finite detected cycle in survivor/witness state;
- budget exhaustion, reported as incomplete rather than blocked/canon.

Axis0 is measured as the root-side unresolved-demand gradient at entry and as
a licensed late readout at return. Alignment means the late readout predicts
the direction and closure of the original demand under controls; it does not
mean copying one scalar from start to finish.

## Only After Core Closure: Develop The 16 Stages

The 16 stages are then tested as owner-specified intelligence-bearing
projections of the same running co-ratchet.

For each stage:

1. give it the same carrier, evidence budget, and task family;
2. preserve its owner-specified terrain, loop role, and Axis-6 sign;
3. measure what transformation or inference it performs;
4. require a held-out competency where it beats stage-erased, role-swapped,
   commuting, static, and label-shuffled controls;
5. require stage removal to damage that competency;
6. cluster stages by measured work without asking for 16 clusters.

A stage earns a distinct intelligence only from reproducible useful work, not
from a distinct channel fingerprint or source-table row.

## Internal Substage Loop Test

Only after a stage has measurable work may its internal processing be tested.

- Generate a count-free set of admissible internal actions.
- Run geometry and entropy selectors independently.
- Close survivors into loops and quotient by cyclic rotation.
- Preserve orientation, nesting, and one inherited Axis-6 sign.
- Do not insert a written starting point.
- Do not ask a selector to choose a Type-1 or Type-2 linear order.
- Four succeeds only if four minimal loop positions recur across seeds,
  enumerations, and held-out tasks without four appearing in the generator,
  stopping rule, clustering rule, or score.

## Two Engine Types And Bidirectional Science

After the 16 stage competencies and internal loops exist, test the two
owner-specified mirrored engine organizations on the same scientific object:

- one direction proposes/expands and the other constrains/reconstructs under
  the owner's deductive/inductive loop semantics;
- both must return measurements, failed projections, and witness receipts;
- each must solve tasks the other does not solve as efficiently;
- running them together must improve held-out prediction or intervention over
  either alone;
- swapping the mirrored roles must break the claimed complementarity.

No linear Ti/Te/Fi/Fe ordering is part of this test.

## Objects, Perception, And Leviathan

Perception is downstream of the running co-ratchet:

```text
independent lossy probes
-> candidate equivalence
-> predictive/interventional survivor
-> object receipt
```

An object is admitted only when it survives unseen probes and supports held-out
prediction or intervention. Leviathan may consume these receipts as evidence,
run agents and workflows, and return measurements. Leviathan cannot mutate
Ratchet canon or promote an object by runtime use.
