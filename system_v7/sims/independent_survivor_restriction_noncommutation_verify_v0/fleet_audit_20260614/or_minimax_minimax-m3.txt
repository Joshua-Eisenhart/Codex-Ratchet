ATTACK (a) — Is the survivor-set noncommutation genuinely emergent, or stipulated?

It is STIPULATED, by three independent devices:

 1. The "local rules" are HAND-PICKED to read H.ever_killed.
    `rule_hist(nb_alive, nb_in_grave) = (nb_alive >= 1) and nb_in_grave`
    is a two-input predicate whose second input only ever flips on if H
    has content. There is no derivation that "local QCA neighbourhood
    rules + topology" produce this predicate; it is asserted in CORE
    (line ~221 of Part A) as a free choice among `rule_hist`,
    `rule_hist2`, `rule_hist_mixed_a/b`, etc. Nothing in the artefact
    argues that the chosen rule is the *generic* behaviour of a QCA
    on a ring. Compare with ratchet_definition §2.2: "to truly earn
    EMERGENCE you must derive the ratchet from lower-level LOCAL
    rules (e.g. QCA neighborhood rules + topology), not just rename
    the defining properties." The artefact does not even attempt
    that derivation; it picks the rule.

 2. The seeder is an explicit contrivance.
    `seeded(C)` (Part A, run_all) prepends a "kill this one cell"
    constraint INSIDE both orderings, so the seeder's own writes
    are the same regardless of order and ONLY the H-content at the
    *interfering* step differs. Without the seeder, the auditor's
    own comment says "a degenerate zero could masquerade as
    'commuting'". The noncommutation is therefore not a property
    of the rule pair; it is a property of the rule pair PLUS an
    engineered initial condition PLUS a wrapping that hides the
    seed from the symdiff.

 3. THE SMOKING GUN: `delta_static_control_x_reactive = 3`.
    This is a HISTORY-INDEPENDENT QCA-style local rule — exactly
    the kind of "lower-level" rule the spec demands in §2.2/§5.5.
    It NONCOMMUTES anyway. So the order-sensitivity is *not* a
    consequence of memory; it is a consequence of X-mutation
    propagating through a CA-style local rule, which is generic
    to any cellular automaton on a ring with sublattice
    interaction. The auditor's own table flags this
    (`static_control_x_reactive_commutes: false`) and tries to
    recover by saying "BUT the extensional control commutes" —
    but the extensional control is a per-cell *absolute* property,

ATTACK (c) — Is the Phi commuting square a real homomorphism test?

No. It is a TAUTOLOGY. `update_lex_factory` (Part A,
lines ~165-176):

    def U(token_set, H):
        return geo_constraint(token_set, H)

This is not a separate lexical implementation. It is a
forwarding function to the same geometric constraint. Phi
is `frozenset(token_set)` (identity on index). So
`Phi o Update_lex = Phi o (geo_constraint) = (geo_constraint)
= Update_geo o Phi` for every input, by construction. The
verdict table admits this verbatim: "1.0 does NOT earn an
independent lexical<->geometric map."

The negative controls (0.78, 0.28) only show that the
factory CAN produce non-1.0 outputs when given a different
geo_constraint; they do not rescue the positive test, which
is just a measurement of "does the same function, called two
ways, return the same thing?". A genuine homomorphism
test would require an INDEPENDENT lexical update
implementation (e.g., a tiny type-checker with its own
constraint grammar) and a check that the two implementations
are STRUCTURALLY aligned on matched inputs. That work is
not done.

ATTACK (d) — Is the GNVW index genuinely computed?

The permutation displacement in `gnvw_index_of_translation`
is real and correctly computed (a winding number around the
ring, minimal signed representative). However:

 - It is the SIMPLEST possible index, not a "GNVW" index

   taxonomic inflation.
 - The JAX leg does NOT independently recompute the GNVW
   index. The JAX result JSON contains
