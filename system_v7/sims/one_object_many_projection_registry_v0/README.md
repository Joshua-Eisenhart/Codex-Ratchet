# one_object_many_projection_registry_v0

Queue item 1 of the Ratchet Runbook (`system_v6/foundations/ratchet_runbook_DRAFT_20260615.md`).

**What it is:** the one-object / many-projections registry — every domain (entropy, geometry, QCA, Hopfield, QIT, spinor, dictionary, OpenHR, OpenFinance, LevOS) mapped as a *projection of one root process: constrained distinguishability*, not as a separate root. Prevents false separation.

**Files:**
- `registry.json` — the rows (runbook §6 schema: name / view_type / preserves / erases / weakest_carrier / stronger_lifts / controls / status).
- `validate_registry.py` — mechanical gate: every row must share the one root, report what it **erases**, carry ≥1 control, and a status label. A row with no erasure or no control is a false-separation/ornamental risk → fails.

**Ceiling:** `SCRATCH_DIAGNOSTIC`. This is the **Mapper pass only** (runbook role 1). The forced-vs-installed and load-bearing-vs-ornamental adjudication of contested rows (spinor, density, QCA-update) is the **multi-model fleet step** (runbook roles 2–4: Minimalist first, then Lift-Advocate, then Control-Auditor) — not asserted here. Where a verdict already exists it is cited (e.g. `ρ` = installed, rung-0 fleet 7/7).
