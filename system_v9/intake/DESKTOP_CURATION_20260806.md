# Desktop curation for the v9 stack

## Result

Twelve recent, high-relevance archives were hash-indexed. None was copied
wholesale. The useful delta is smaller than the archive estate and is recorded
below as implementation requirements, candidate science, or already-preserved
source.

## ConstraintBox delta

The audited custody pack contributes a sound pattern, not an automatic code
promotion:

1. a controller creates an exact artifact manifest outside the sealed scope;
2. the consumer is given an independently recorded hash of that manifest;
3. every declared path is resolved and must remain inside the artifact root;
4. declared and actual file sets must match exactly;
5. subprocesses use argument arrays, never `shell=True` command strings;
6. producer booleans such as `all_pass` are recorded but never trusted;
7. byte custody remains below semantic evaluation, ClaimGate admission, and
   release.

The original candidate packs are not retained as active CB code because their
audits reproduced fail-open empty discovery, path escape, an approximate
cleanliness threshold, a broken self-hashing manifest, and unsafe shell
execution. A clean port of the audited v2 custody pattern is v9 follow-up work,
not a reason to enlarge the five-tool CB dependency slice.

## Sim Engines and manifold delta

The CB/Sim foundation handoff is useful because it keeps two outcomes apart:

- bounded NumPy/JAX/PyTorch/Julia workloads executed;
- the requested paired `base -> 2 -> 4 -> 16` genealogy failed.

The failure is retained as a construction requirement: every child needs a
named parent hash, a newly added constraint, and a measurable change in map,
geometry, trajectory, or entropy readout. It is not a failure of package
installation and cannot be converted into a CB-core claim.

## QIT-engine delta

The reality-checkpoint audit gives a usable gate order:

| Gate | Required result | Current status |
|---|---|---|
| G0 | one canonical schedule consumed directly by four loop adapters and two no-reset engine adapters | candidate exists; common source binding failed |
| G0v | independent consumer rehashes inputs and sources, recomputes outputs, and runs schedule-permutation controls | required next |
| G1 | stage maps lifted onto explicit QIT APIs with CPTP/Choi or equivalent validity and cross-lane comparison | not earned |
| G2 | four-loop/two-engine behavior under common loads, no reset, basin observables, and destructive controls | not earned |
| G3 | per-stage ability tournament with ablation/replacement loss | not earned |

Four-lane quantum-Hopfield execution is evidence that bounded QIT computation
exists. It is not evidence that the two eight-stage engines or their sixteen
abilities exist.
